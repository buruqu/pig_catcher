## 1. 范围键

业务数据统一使用以下范围键：

```text
scope_id = platform + ":" + group_id
player_id = scope_id + ":" + platform_user_id
```

不得使用显示名作为身份键。显示名只保存为快照，用于渲染；用户改名不影响资产归属。

## 2. 核心对象

| 对象 | 说明 | 关键标识 |
| --- | --- | --- |
| 群范围 | 一套独立游戏世界 | `scope_id` |
| 玩家 | 某用户在某群的游戏身份 | `player_id` |
| 猪模板 | 名称、品质、素材和属性范围定义 | `pig_template_id` |
| 猪实例 | 一次抓取产生的独立资产 | `pig_instance_id` |
| 群模板授权 | 将 6 星模板授权给指定群 | `scope_id + pig_template_id` |
| 美食模板 | 名称、品质、食谱倾向、素材和效果定义 | `food_template_id` |
| 美食实例 | 一次做菜产生的独立资产 | `food_instance_id` |
| 图鉴条目 | 玩家曾经获得某模板的事实和统计 | `player_id + template_id` |
| 群纪录 | 某猪模板的最大体型或最大重量 | `scope_id + template_id + record_type` |
| 全群绝对纪录 | 不限模板的最大体型和最大重量 | `scope_id + record_type` |
| 巨物目击 | 达到体型或重量阈值的群内历史事件 | `sighting_id` |
| 余额与账本 | 当前猪币及每次变动原因 | `player_id`, `ledger_entry_id` |
| 升级 | 猪饲料和厨具等级 | `player_id + upgrade_type` |
| 道具库存 | 一次性道具持有数量 | `player_id + item_id` |
| 交易报价 | 锁定物品并等待接收方处理 | `trade_id` |
| 展示设置 | 排行榜默认展示的猪和美食 | `player_id` |
| 稳定统计 | 抓猪、做菜、赠送和成交等累计行为 | `player_id` |
| 美食效果队列 | 等待兼容动作的效果，以及按当前时段/当天到期的额度效果 | `effect_entry_id` |
| 抓猪额度加成 | 不可叠加的滚动 7 天全时段加成与封顶永久加成 | `player_id` |
| 玩家限制 | 插件访问、永久赠送/收赠、永久交易黑名单及可到期额度上限 | `player_id + restriction_type` |
| 幂等操作 | 消息与业务结果的唯一映射 | `scope_id + message_id + command_name` |

## 3. 模板与实例分离

模板描述“这种猪或菜是什么”，实例描述“某次实际获得了什么”。

### 3.1 猪模板

计划字段：

- 稳定模板 ID、名称、品质、描述、素材路径和素材校验值
- 公共或群定制范围
- 体型最小值、最大值、分布参数和 `mini / standard / giant` 体型档案
- 重量最小值、最大值和体型关联参数
- 肥瘦率分布、食谱标签和联动标签
- 群专属六星猪对应的同群定制六星菜模板 ID
- 启用状态、版本、来源、许可和授权状态

模板 ID 一旦发布不得因改名而变化。素材替换通过模板版本和校验值追踪。

### 3.2 猪实例

计划字段：

- UUID 主键和全库唯一的展示短编号：旧编号原样保留；新自动编号为 8 位完整字母数字，
  管理员手动编号允许 4 至 16 位，查询和唯一性均不区分英文大小写
- `scope_id`、当前持有者、来源消息、模板版本
- 品质、体型、重量、肥瘦率、官方价值
- 抽取时的概率配置版本、结算前数值等级与随机结果快照
- 创建时间、锁定状态、处置状态、处置时间和玩家可切换的 `is_favorite` 收藏保护标记

品质和数值快照写入实例，后续调平概率或模板范围不会修改历史资产。

### 3.3 美食实例

计划字段：

- UUID 主键和展示短编号
- 原料猪实例 ID、食谱模板、品质、份量或重量、肥瘦类别
- 官方价值、效果 ID、效果参数快照
- 结算前数值等级、厨具、消耗品和概率规则版本
- 当前持有者、锁定状态、使用或处置状态和玩家可切换的 `is_favorite` 收藏保护标记

原料关系只用于审计和展示。猪被消耗后保留不可恢复的历史行，不做物理删除。

## 5. 状态机

### 5.1 资产状态

```text
ACTIVE -> LOCKED_FOR_TRADE -> ACTIVE                 报价拒绝、取消或过期
ACTIVE -> LOCKED_FOR_TRADE -> ACTIVE + OWNER_CHANGED 成交后转移给接收方
ACTIVE -> ACTIVE + OWNER_CHANGED                     赠送后转移给接收方
ACTIVE -> SOLD                                       官方售卖
ACTIVE -> CONSUMED_FOR_COOKING                       猪被做菜
ACTIVE -> CONSUMED                                   美食被使用
ACTIVE/LOCKED_FOR_TRADE -> ADMIN_REMOVED             管理员精确移出玩法
```

`OWNER_CHANGED` 是审计事件而不是资产终态。状态变化和持有者变化只能由领域服务执行，任何资产在同一时刻最多被一个有效交易锁定。

### 5.2 交易状态

```text
PENDING -> ACCEPTED
PENDING -> REJECTED
PENDING -> CANCELLED
PENDING -> EXPIRED
```

`ACCEPTED` 是唯一会转移资产和猪币的状态，且转移与状态变更在同一数据库事务中完成。

## 6. 关键不变量

1. 资产只能有一个当前持有者。
2. 非 `ACTIVE` 资产不能重复售卖、赠送、做菜、吃掉或发起新交易。
3. 普通购买、升级和交易不得透支；只有审计式管理员扣币可产生负余额，且缓存余额仍必须与不可变账本逐笔对账。
4. 6 星模板只有在当前范围授权且启用时才可抽取。
5. 跨范围的赠送、交易、排行和资产选择一律拒绝。
6. 1 至 5 星猪不可能生成 6 星美食。
7. 6 星猪的出菜品质只能是 5 星或 6 星，基础概率为 90% 和 10%；普通层可由超级主厨香料、“一猪六吃”和最多 5 层猪饺叠加至最高 50%，六星菜独占效果可直接改写两者比例。
8. 6 星猪产生 6 星菜时，只能使用该猪模板绑定的、已授权且属于同一群的定制六星菜；绑定缺失或失效时整笔回滚。
9. 图鉴“曾获得”只增不减；重复获得只更新计数与最佳值。
10. 最大体型和最大重量纪录独立更新，数值相同不覆盖更早纪录。
11. 同一命令消息只能产生一个业务收据。
12. 图片生成或发送失败不改变已经提交的业务结果。
13. 赠送只发生一次所有权转移，不产生猪币或经验。
14. 成交必须产生卖方正数、买方负数的两条同额猪币分录，合计恒为零。
15. 接受时余额不足的报价保持 `PENDING`，直到拒绝、取消或过期。
16. 抓猪与做菜历史统计来自行为收据和稳定计数，不随资产转移、售卖或消耗倒退。
17. 全群绝对纪录与巨物目击按 `scope_id` 隔离；其他群不可查询或参与排序。
18. 美食效果只在兼容动作成功事务中消费；普通做菜提质等待 1 至 5 星原料，普通六星菜概率增量与六星独占做菜效果等待 6 星原料。
19. 滚动 7 天每时段额度不可重复叠加；从食用时刻起七天后的对应额度窗口仍完整生效，
    窗口结束时失效。永久每时段额度每次增加 1，累计上限为 5，达到上限时美食不得消耗。
20. 普通五星“一猪六吃”可与超级主厨香料叠加并封顶 50%；当前两者分别为 `+15` 与
    `+10` 个百分点。任何六星菜动作效果触发时，必须从纯基础权重结算，等级、饲料/厨具、
    道具与其他菜品不参与且不消耗。
21. 一盒油炸猪只增加当前窗口基础额度，猪寿司拼盘增加今天当前及后续每个窗口的基础额度；两层可相加，同类效果在对应窗口/当天不可重复食用。
22. 旧版额外抓猪次数只在当前窗口基础额度已经用完后消费，并在北京时间次日零点失效；已经消费的次数不会因 09:00、12:00 或 19:00 刷新而恢复。
23. 手动额度重置只允许指定一个精确 `scope_id`，先在线备份，再写入 `catch-quota-window-reset` 审计事件；不得删除历史回执、终身统计或资产。
24. 赠送/收赠黑名单与交易黑名单分别持久化且默认无到期时间；赠送或交易的任一参与方命中对应黑名单时整笔拒绝。
25. 违规抓猪额度上限优先于基础、时段、当天、周、永久和额外次数；处罚到期后只恢复正常额度，不改变永久社交黑名单。
26. 面板黑名单批量操作必须先解析目标群中的全部既有成员；任何成员不匹配时整批拒绝，不能创建猜测身份或跨群限制。
27. 面板公告一次触发只允许领取一次发送权；平台返回失败或进程重启后不自动重发，由管理员确认外部权限和上下文后重新发起。
28. 批量售卖和批量做菜对每个 `collection_id` 非空的联动猪模板保留一个最高官方价值实例；
    同价值取实例 ID 最小者，重复联动实例可以处理，该保护不依赖玩家开关。
29. `batch_keep_highest=1` 时，当前批次品质范围内的普通猪或美食按模板各保留一只最高价值实例；同价值取实例 ID 最小者，锁定资产不参与选择也不参与处理。
30. 两组实际 QQ 群对应四个独立作用域；玩家、资产和账本不跨作用域合并，但群专属模板的用户可见语义必须同步。
31. 管理员全员猪币调整按当前 `scope_id` 的已登记玩家解析，并在单一事务中逐玩家写账本；任一分录失败时整批回滚。
32. 管理员生成资产不增加抓猪/做菜统计、经验或玩法奖励；手动短编号必须在猪与美食全库中唯一。
33. `ADMIN_REMOVED` 资产保留历史实例与图鉴，但不得再进入背包、展示、赠送、交易、售卖、做菜或排行榜纪录。
34. 插件访问黑名单优先阻止普通玩家命令和全部社交流转；配置管理员不得被该运行时名单锁死。
35. 玩家级额度重置只改变该玩家当前窗口的有效计数起点，不删除回执，不影响同群其他玩家。
36. 资产短编号只允许 4 至 16 位 ASCII 字母数字，输入统一转为大写比较；猪猪和美食共享
    应用层唯一性检查。Schema 16 迁移只重建约束与排序规则，不改写任何旧编号字符串。
37. 自动监管至少需要两个主动上游账号；单来源与单接收方的一对一流转不得创建处罚。
38. 监管提醒只有从 `CLAIMED` 成功写为 `SENT` 后才算送达；未送达提醒不得启动后续升级计数。
39. 被监管阻断的赠送或接受交易必须在扣款、资产转移和统计增加之前返回，并与案件事件和
    幂等收据在同一事务中提交。
40. 赠送接收方默认是被动成员；只有其主动参与已接受交易或后续主动流转时，才可按对应行为处理。
41. 自动 `social/plugin` 限制只能写入 `anti_abuse_holds` 且必须有到期时间；永久黑名单仍只写
    `player_restrictions` 并由管理员维护。
42. 相同消息回执、相同提醒阶段和相同成员事件必须可去重，不得因适配器重投多次升级。
43. 普通抓猪收据的 `catch_quota_cost=1`，六星菜专属抓猪为 `0`；窗口额度只累加该字段，
    冷却、终身统计与违规处罚硬上限仍统计全部成功抓猪。
44. 猪饺的未消费效果最多允许 5 层；第 6 次食用必须拒绝且保留美食。下一次六星猪成功
    做菜时，已选择的 1 至 5 层在同一事务中全部消费，并与普通六星菜增益共同受 50% 上限约束。
45. 联动定向抓取只能从当前作用域已授权、已启用且带 `collection_id` 的模板中选择；
    固定品质分布不得被概率道具、等级、饲料或普通概率菜改写，被排除的资源保留不消耗。
46. 黑猪麻汤圆同时占用普通抓猪概率与体型效果位；五星巨物模板偏向只改变同品质候选
    模板之间的选择权重，不改变品质结果，也不得跨群借用模板。
47. 猪咪莓蛋糕只等待 1 至 5 星猪做菜，把五星结果提高到至少 85%；使用六星猪、动作失败
    或事务回滚时必须保留效果。
48. 群级六星菜效果按精确 `scope_id` 保存；每名玩家的可用次数通过独立使用行延迟创建，
    因此效果生效后才首次使用插件的同群玩家也能获得自己的次数，但即时猪币只发给使用
    菜品或重置时已经登记在该作用域的玩家。
49. 神龙化猪七星云海锅在每名玩家下一次抓猪时优先于个人六星菜、普通菜、等级、饲料和
    道具，以纯基础概率对五星、六星应用 `×8`；被排除资源保持不消耗。
50. 糖醋排骨群级倍率与猪鼻蛋包饭每人一次的额外抓猪 `×1.004` 可以叠加一个道具和非六星
    菜，但多个群级六星菜倍率不相乘，只选择 5/6 星综合倍率最高者；更强群效果还有专属额度
    时蛋包饭机会不消费，更强效果只剩时效倍率时由蛋包饭提供本次额外额度；联动固定分布和
    个人六星独占接管时不参与结算。
51. 群级效果最晚到期点为使用时所在额度窗口的起点加一天；查询必须使用 `starts_at <= now <
    expires_at`。猪鼻蛋包饭还受个人用量约束：成功使用一次后立即退出候选，不得继续加权。
52. 抓猪结果只有在群级概率或该效果提供的专属额度实际参与结算时，才可展示来源玩家的
    `display_name`；用户可见图片和文字不得显示 `platform_user_id` 或内部 `player_id`。稳定平台
    ID 仅保留于群效果来源、随机快照和幂等回执结构；过期或被互斥保留的效果不得署名。
53. 正常抓猪额度必须按基础、永久、滚动七天、当前时段、今日时段和旧版共享池分层相加；
    个人或群级六星专属次数不进入正常额度，也不增加普通额度成本。
54. 账号活跃度只由当前精确群指定窗口内的非命令消息数量和活跃日期构成；聊天正文不得写入
    插件数据库或监管证据，历史查询失败时活跃层级为未知。
55. 只有双方均为活跃主账号且存在双向赠送时，相关赠送事件才可从本轮监管图排除；交易、
    单向赠送、涉及未知/疑似小号或当前已有限制的操作不得借此放宽。
56. 疑似小号必须同时满足低消息、低活跃日、新插件账号和低玩法行为四项条件；严格模式仍需
    至少两个主动来源，单一小号来源不得自动创建处罚。
57. 猪鼻蛋包饭的全群猪币、每人 1 次额外抓猪 `×1.004` 与食用者个人
    `next-six-star-cook` 两次机会必须在一次吃菜事务中同时登记；额外抓猪不增加正常额度
    计数，用完后倍率立即失效；非六星原料做菜不得消费个人做菜机会。
58. 糖醋排骨隐藏判定只在该群效果本次提供专属额度时执行，每次独立使用一个 `[0,1)` 随机值；
    `roll < 0.10` 时用 `×10.04` 替换本次 `×1.007`，不能把二者相乘。命中和随机值进入快照。
59. 雾蓝键盘大福的五次专属额度只在食用时所在窗口内有效，并固定使用四/五/六星
    `61.5385/30.7692/7.6923`；猪保千轮盘产生的六档等概率五连与下一次必出六星均是
    独占抓猪层。三者均不得读取或消耗普通概率菜、道具、等级和饲料修正。
60. 独占层需要当前群存在相应品质模板；若六星模板不可用，无法兑现的六星份额按既有缺档
    规则转入五星，不得跨群借用六星素材。必出六星效果只有成功抓猪事务才消费。
61. 配置管理员对应的 `player_id` 必须在当前拟议流转检查和历史图构建两个阶段同时排除；不得为
    管理员参与的流转创建案件、成员、提醒、限制或监管事件。人工三类黑名单不属于自动监管豁免。
62. 监管单生命周期固定为 `created_at + 24h`，不能因后续证据更新而顺延；达到到期点后必须将
    案件改为 `dismissed`、当前 `score` 归零、成员提醒/累计归零、未投递通知失效并释放活动限制。
63. `/猪管监管` 只查询未关闭、未撤销且 `created_at` 未满 24 小时的案件；关闭或撤销案件不得
    再领取通知。`anti_abuse_events` 和已发送通知继续作为不可变历史保留。
64. 全局监管重置必须使用 SQLite 在线备份后进入单一立即事务；全部案件即使原本已经撤销也要
    统一把当前分数归零，并为每案追加零分重置事件、为每个涉及作用域追加通用审计事件。
65. 收藏保护属于资产实例而不是模板：旧实例迁移后默认未收藏；收藏实例不得被做菜、吃菜、
    官方售卖、赠送、交易锁定或任何自动/批量选择处理，主动展示不属于处置动作，可以使用收藏实例。
66. 名称直选的处置操作先排除收藏和锁定实例，再按官方价值、获得时间、实例 ID 选择最低者；
    展示直选按官方价值最高者选择。`名称#短编号` 始终保留精确语义，但精确指定收藏资产做处置时也必须拒绝。
67. `/批量售卖 美食 <菜名>` 只处理该名称的一至五星活动菜品；先排除收藏/锁定资产，再应用
    玩家批量保留偏好，整批状态变更、猪币账本和幂等回执必须在一个事务中提交。

## 7. 精确选择规则

同名资产可能有多只，名称直选必须使用稳定且公开的顺序，不得依赖数据库偶然返回的“第一只”。

- 做菜、售卖、赠送和交易：只填名称时选择最低官方价值的未收藏、未锁定同名资产；同价值依次按获得时间和实例 ID。
- 展示：只填名称时选择最高官方价值的同名资产，允许收藏资产；同价值依次按获得时间和实例 ID。
- 详情：继续使用 `名称#短编号` 精确定位，避免只读结果含糊。
- 模糊匹配：只用于候选提示，不直接执行消耗性动作。
- 短编号冲突：创建时重新生成并由数据库唯一约束兜底；资产转移不改变短编号。
- 短编号大小写：`Pig9Fun`、`PIG9FUN` 与 `pig9fun` 指向同一编号；不得创建仅大小写不同的重复编号。
- 低星快捷操作：仅当 `/做菜`、`/吃菜`、`/售卖猪猪` 或 `/售卖美食` 完全省略选择器时，按官方价值、获得时间和实例 ID 稳定选择最低价值且未收藏、未锁定的 1 至 3 星资产。

## 8. 事务边界

以下操作必须各自在单个事务中完成：

- 抓猪：限额检查、额外次数、个人/群级美食效果消费、道具消耗、实例创建、奖励、经验、图鉴、品种纪录、全群绝对纪录、巨物目击、稳定统计和幂等收据。
- 做菜：原料锁定、批量保护选择、美食效果与道具消耗、猪状态变更、美食创建、奖励、经验、图鉴和收据。
- 官方售卖：所有权检查、批量保护选择、资产状态变更、猪币入账和收据；批量售卖也必须在一个事务中完成。
- 赠送：双方范围检查、监管预判、案件/提醒或限制、所有权转移、图鉴更新和收据。
- 接受交易：报价检查、监管预判、案件/提醒或限制、两条零和账本分录、所有权转移、解锁、双方稳定统计和收据。
- 批量处罚/面板黑名单：精确群成员校验、三类限制写入、相关待处理交易取消与解锁、审计事件。
- 管理员猪币：目标解析、逐人余额更新、不可变账本、审计事件和幂等收据；全员操作整批原子提交。
- 管理员资产：当前群模板授权、唯一编号、实例/图鉴写入，或关联报价取消、展示清理与 `admin-removed` 状态、审计和收据。
- 群内黑名单/个人额度：精确玩家解析、单类限制或玩家级重置事件、关联报价处理、审计和幂等收据。
- 吃菜：美食状态变更、个人和/或群级持久效果登记、全群逐玩家猪币账本、经验和收据；
  猪鼻蛋包饭的个人两次做菜机会与群效果必须原子创建。
- 糖醋排骨机会：群窗口重置、群级倍率与专属额度登记、全群逐玩家猪币账本、机会消费、审计和幂等收据。

群公告不参与游戏资产事务。插件先写入 `announcement-send-claimed` 审计领取一次发送权，
再调用当前群最近消息流，最后追加成功或失败审计；任何结果都不自动重试。

渲染在事务提交后进行。发送前通过条件更新把收据从 `PENDING` 领取为 `CLAIMED`，再执行图片或文字发送；重复消息和重启恢复不得重新领取 `CLAIMED` 或 `SENT` 收据。渲染状态和发送状态写回 `command_receipts`，优先保证不重复公示，并允许用户通过查询命令找回极端崩溃窗口中未发出的结果。

糖醋排骨取得重置机会、神龙化猪七星云海锅完成全群结算，以及食用者实际执行糖醋排骨重置，均复用各自原命令的唯一收据发布一次全群大事件通告，不另建第二条发送路径。糖醋排骨食用通告只陈述“取得资格”，不得提前宣称额度、猪币或倍率已经发放；正式重置通告只能在重置事务提交后生成。若图片渲染失败或已关闭，原收据必须保存语义完整、可独立阅读的事件文字回退。
