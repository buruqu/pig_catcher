# 命令与交互协议

## 1. 总体规则

- 所有玩法只通过显式斜杠命令触发，不监听普通消息。
- 命令名、参数提示和错误信息以简体中文为主。
- `/抓猪帮助` 返回纯文字；其他查询和成功结果优先返回渲染图。
- 参数解析、随机计算和结算均为确定性业务代码，不调用 LLM。
- 同一来源消息重复投递时，返回既有结果或“已处理”提示，不重复产生资产和公示。
- 赠送、交易和显式指定的消耗/售卖必须使用精确资产选择器；四个低星快捷命令可完全省略选择器。

## 2. 资产选择器

标准格式：

```text
名称#短编号
```

示例：

```text
/做菜 粉红小香猪#A19F2C3D
/售卖美食 红烧肉#7D3B81EF
```

仅当名称在当前用户的有效库存中唯一时，允许省略短编号。候选不唯一时只展示候选，不执行动作。

完全不填写名称是另一种明确语义：`/做菜`、`/吃菜`、`/售卖猪猪` 和
`/售卖美食` 会稳定选择最低价值且未锁定的 1 至 3 星资产。该规则不扩展到赠送、
交易、详情或展示设置。

## 3. 用户命令

### 3.1 帮助与档案

| 命令 | 参数 | 行为 | 输出 |
| --- | --- | --- | --- |
| `/抓猪帮助` | 可选主题 | 显示完整命令和可复制示例 | 纯文字 |
| `/抓猪档案` | 无 | 显示等级概率、经验、猪币、升级、统计和展示物 | 图片 |
| `/抓猪详情` | 猪选择器 | 显示单只猪的属性、描述、来源和纪录 | 图片 |
| `/美食详情` | 美食选择器 | 显示单道菜的属性、效果、来源和价值 | 图片 |

帮助主题可包括：`抓猪`、`背包`、`做菜`、`商城`、`交易`、`排行`。
默认帮助只展示命令和必要的资产选择提示，不展示版本、开发轮次或功能宣传文字；
`/抓猪档案` 与 `/抓猪详情` 继续可用，但不再占用默认帮助列表。
档案中的等级概率区必须同时显示“等级单独作用时”的 4 至 6 星抓猪合计概率、
普通做菜高档权重增幅和 `Lv.21` 封顶提示；荣誉称号不得被描述为概率来源。

### 3.2 抓取与库存

| 命令 | 参数 | 行为 | 输出 |
| --- | --- | --- | --- |
| `/抓猪` | 无 | 抽取一只当前群可用的猪 | 单次收获图 |
| `/抓群友` | 无 | `/抓猪` 的完全等价别名 | 单次收获图 |
| `/猪猪背包` | 可选页码、品质、排序 | 查看仍持有的猪 | 背包图 |
| `/美食背包` | 可选页码、品质、排序 | 查看仍持有的美食 | 背包图 |
| `/猪猪图鉴` | 可选品质 | 按品质完整列出可见猪模板 | 完整图鉴长图 |
| `/美食图鉴` | 可选品质 | 按品质完整列出可见美食模板 | 完整图鉴长图 |
| `/猪猪纪录` | 可选页码 | 查看当前群按模板维护的体型与重量纪录 | 纪录图 |

建议筛选语法：

```text
/猪猪背包 2 品质=4 排序=价值
/美食图鉴 品质=未收集
```

允许的排序包括：`获得时间`、`品质`、`价值`、`体型`、`重量`、`名称`；默认排序为 `价值`。
图鉴不填写页码；可使用 `品质=1..6` 或 `品质=未收集` 筛选，结果仍一次完整展示。

当前开放：`/抓猪`、`/抓群友`、`/抓猪档案`、`/抓猪详情`、`/猪猪背包`、
`/猪猪图鉴`、`/猪猪纪录`、`/使用道具`、`/取消道具`，以及下文第四轮做菜、
美食、商城、购买、官方售卖和猪币账本命令，以及第五轮赠送、交易、展示和排行命令。

### 3.3 做菜、吃菜与道具

| 命令 | 参数 | 行为 | 输出 |
| --- | --- | --- | --- |
| `/做菜` | 可选猪选择器 | 消耗指定猪；省略时处理最低价值低星猪 | 料理结果图 |
| `/吃菜` | 可选美食选择器 | 消耗指定美食；省略时品鉴最低价值低星菜 | 使用结果图 |
| `/使用美食` | 可选美食选择器 | `/吃菜` 的别名 | 使用结果图 |
| `/使用道具` | 道具名称 | 将道具装备到下一次兼容动作 | 装备回执图 |
| `/取消道具` | 抓猪或做菜 | 取消装备并返还尚未消耗的道具 | 回执图 |

装备的道具只在兼容动作成功提交时消耗。参数错误、冷却、背包选择冲突和数据库失败都不消耗道具。

### 3.4 商城与官方售卖

| 命令 | 参数 | 行为 | 输出 |
| --- | --- | --- | --- |
| `/猪猪商城` | 可选分类 | 单页查看全部升级、逐级概率和消耗品 | 商城图 |
| `/购买` | 消耗品名称、可选数量 | 购买一种消耗品 | 购买回执图 |
| `/升级` | `猪饲料` 或 `厨具` | 原子购买下一级永久升级 | 购买回执图 |
| `/售卖猪猪` | 可选猪选择器 | 指定售卖；省略时卖最低价值低星猪 | 售卖回执图 |
| `/售卖美食` | 可选美食选择器 | 指定售卖；省略时卖最低价值低星菜 | 售卖回执图 |
| `/批量售卖` | `猪猪` 或 `美食` | 原子售卖全部未锁定 1 至 3 星资产 | 批量回执图 |
| `/猪币账本` | 可选页码 | 查看当前群个人不可变猪币流水与余额 | 账本图 |

购买数量必须是正整数并受单次上限约束。永久升级从 `Lv.0` 开始，达到 `Lv.5` 后不可继续升级。
商城固定列出猪饲料 `Lv.0-5` 的 4 至 6 星合计概率，以及厨具 `Lv.0-5`
对普通高档菜的相对权重增幅，并高亮玩家当前等级；六星猪固定 90/10 的例外必须同屏说明。
上述命令已在第四轮开放；所有购买、奖励与售卖写入不可变账本，并在同一事务中更新缓存余额。

### 3.5 赠送与交易

| 命令 | 参数 | 行为 | 输出 |
| --- | --- | --- | --- |
| `/猪猪赠送` | 猪选择器、@用户 | 立即无偿转移猪 | 双方信息回执图 |
| `/美食赠送` | 美食选择器、@用户 | 立即无偿转移美食 | 双方信息回执图 |
| `/猪猪交易` | 猪选择器、@用户、猪币 | 创建限时报价并锁定猪 | 报价图 |
| `/美食交易` | 美食选择器、@用户、猪币 | 创建限时报价并锁定美食 | 报价图 |
| `/接受交易` | 交易号 | 原子完成猪币和物品转移 | 成交图 |
| `/拒绝交易` | 交易号 | 拒绝报价并解锁物品 | 回执图 |
| `/取消交易` | 交易号 | 发起方取消待处理报价 | 回执图 |
| `/我的交易` | 可选状态 | 查看本人相关报价 | 列表图 |

交易约束：

1. 发起方和接收方必须是当前群的不同用户。
2. 价格为正整数，且不超过配置的单笔上限。
3. 默认有效期 5 分钟，可由配置调整。
4. 接收方接受时才扣款；余额不足时交易保持待处理，直到拒绝、取消或过期。
5. 已售卖、已赠送、已消耗或被其他交易锁定的物品不能报价。
6. 赠送和报价必须携带恰好一个平台结构化 `@`，不能只凭昵称文本识别接收方。
7. 同一资产同时最多属于一笔待处理报价；接受并发竞争只有一次能成交。

### 3.6 排行与展示

| 命令 | 参数 | 行为 | 输出 |
| --- | --- | --- | --- |
| `/猪猪排行` | 可选类型和页码 | 查看当前群排行榜 | 排行图 |
| `/设置展示` | `猪猪` 或 `美食`、选择器或 `取消` | 设置或清除默认展示物 | 回执图 |

排行类型定义：

| 类型 | 排序依据 |
| --- | --- |
| 默认或 `综合` | 猪图鉴完成率与美食图鉴完成率的加权总分 |
| `抓猪` | 累计成功抓取次数 |
| `美食` | 累计成功做菜次数 |
| `价值` | 当前有效猪与美食的官方价值总和 |
| `巨物` | 单只猪的体型、重量标准化综合分 |
| `数量` | 当前有效猪与美食件数总和 |
| `猪币` | 当前猪币余额 |

默认榜显示前十用户、两类图鉴进度、指定展示猪、指定展示美食和关键统计。未设置展示物时自动使用当前最有价值的有效资产，但不写回用户偏好。

累计抓猪和做菜次数保存在稳定行为统计中，不会因为赠送、交易、售卖、做菜消耗或吃菜而倒退。排行榜和展示数据只在当前 `platform + group_id` 范围内查询。

## 4. 管理能力

首版不依赖群聊管理命令，优先通过 MaiBot 中文配置面板提供：

- 插件总开关、群黑白名单和用户黑白名单
- 冷却、每日次数、概率版本和经济参数
- 当前群 6 星素材启用、停用和授权状态
- 交易开关、价格上限和报价有效期
- 渲染尺寸、字体和图片质量
- 数据库备份、账本检查和审计日志入口

需要群内紧急管理命令时，只添加最小集合，并强制校验 MaiBot 管理权限和 Bot 管理员列表。

## 5. 响应顺序

每个改变状态的命令按以下顺序处理：

1. 解析命令与身份范围。
2. 检查插件、群和用户访问策略。
3. 解析唯一资产并验证冷却、配额和权限。
4. 在数据库事务中执行业务结算并写入幂等收据。
5. 提交事务。
6. 根据收据生成图片。
7. 发送图片；失败时记录日志并发送文字兜底。
8. 更新收据的渲染和发送状态。

不得先发“成功”再尝试提交数据库，也不得因发图失败回滚已提交结算。

## 6. 文字兜底最小内容

图片失败时，文字至少包含：

- 操作名称和是否成功
- 资产名称、品质和短编号
- 本次猪币与经验变化
- 当前余额或关键状态
- 交易号、纪录或其他本次独有信息

兜底文字不得包含本地文件路径、堆栈、数据库 SQL 或素材授权信息。
