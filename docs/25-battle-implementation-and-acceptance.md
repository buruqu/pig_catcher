## 2. 参战与生命周期

以下为本轮补齐的运营取值，不冒充早期已经明确的用户决定：

- 每名玩家在**北京时间每天**有一次主动和一次应战额度；接受成功才同时扣各自角色额度。
  邀请跨日时按接受日扣，两个角色互不占用。取消、拒绝、五分钟邀请超时不扣额度。
- 待接受邀请也占本群唯一场地；一次成功邀请后，邀请者 60 秒内不能再发，避免反复打扰。
  邀请不锁猪；接受时重新核验双方所有权、出战配置、强化、属性、库存、占用与黑名单。
  双方都必须已设置战斗猪，受邀者明确发指令表示应战；不伪造“在线检测”。
- 开战后占用双方实例。有效推进会把行动截止延后十分钟；查状态、查历史、重复消息或
  已完成动作不延长。任何一方长时间不行动，全场无奖励结束，不假判另一方自然获胜。
- 认输须再确认，不退已经扣除的日次数，不发战利品；取消/超时也不能刷自然胜场。
  服务器/事务异常回滚，不算认输或力竭。重启后继续同一场、同一随机游标，不重新开局。
- 截止时间持久化；下次相关操作先处理本群过期场次，释放猪并退回未触发器具。
  不为每个玩家启常驻定时器，不主动刷群。闲置期间没有自动发送超时消息。
- 新配置 `features.battle_enabled` 只控制开发线对战入口；战利品同时遵守抓猪总开关。
  关闭功能不清空成长/保护/历史；已有超时活动仍可在正常相关操作时安全释放。

## 3. 原定轮盘与结算顺序

### 招式盘

所有招式的**出现权重均为 1**。宿傩每项 1/9，五条每项 1/10；升级不改变这些概率。

| 宿傩猪（9 项） | 五条猪（10 项） |
| --- | --- |
| 黑闪：再抽两次 | 术式顺转·苍：+13 |
| 解：+10 | 术式反转·赫：+20 |
| 捌：+15 | 肘击·苍拳：+14 |
| 灶·开：+21 | 无下限·防御：+10 |
| 领域展开·伏魔御厨子：+35 | 黑闪：再抽两次 |
| 束缚·贷款：再抽一次、待用×2、下回合扣1招 | 无下限·瞬移：+14 |
| 反转·修复：+14 | 虚式·茈：+24 |
| 肘击：+7 | 领域展开·无量空处：+30 |
| 网格斩：+12 | 反转·修复：+14 |
| — | 无限制·茈：+35 |

表中数值是胜利权重，不是概率百分点；“修复”本身只加数值，不自动治疗。
战斗招式仅在对战内部生效，不会发动普通抓猪里的伏魔御厨子、苍、赫或虚式奖励。

### 出招数与伤势盘

| 盘 | 选项 | 对应抽取权重 |
| --- | --- | --- |
| 正常出招数 | 1、2、3、4、5 | 5、4、3、2、1 |
| 重伤出招数 | 1、2、3、4 | 5、4、3、2 |
| 初始风险伤势 | 轻伤、重伤、力竭、掌握核心 | 6.5、2.5、0.5、0.5 |
| 轻伤风险伤势 | 轻伤、重伤、力竭、掌握核心 | 2.5、6、1、0.5 |
| 重伤风险伤势 | 轻伤、重伤、力竭、掌握核心 | 1、2.5、6、0.5 |

每场双方基础胜利权重为5。当前回合胜率 = 自己当前完整结算权重 ÷ 双方完整结算权重之和。
若本回合新增净权重为 `G_R` 且未力竭，后续回合只迁移 `(G_R + 1) // 2`；每一轮独立
向上取整且只折半一次。因此第3回合为 `5 + ceil(G_1/2) + ceil(G_2/2) + G_3`，基础5不折半。
双方本回合都出完后才抽胜负，败者自动抽伤势盘。输入顺序不改变预先固定的各自抽样序列。

- 贷款的每次再抽照常发生、每次均加一笔下回合欠招；连续贷款只保留一份待用 ×2，
  不是 ×4，也不是排队两次翻倍。黑闪等功能招式不消耗待用翻倍。
- 下回合实际招数 = `max(0, 抽到招数 - 欠招)`，超额欠招到此清零，不继续追下一回合。
  零招只表示这回合不能行动，不直接判负；双方零招仍按基础5与历史折半继承抽胜负。
- 轻伤提升风险但不解除既有重伤；首次重伤进入重伤盘，后续数值招式减 1。
  反复受伤在这三套固定盘中单调提升风险，不额外无限抬高伤势权重。
- 每次掌握核心都解除重伤、恢复正常出招数盘并使后续数值招式 +1；**核心无叠加上限**。
  历史伤势风险不下降，已经提交的回合新增与折半继承不追溯改写。
- 普通数值招式：`max(0, 基础数值 + 强化等级 + 核心层数 - 重伤修正) × 待用倍率`。
  之后再加个体/护腕独立收益。纯功能招式无数值收益，不吃强化、核心或重伤数值修正。
  今后功能招式若明确新增正数收益，该正数部分可复用相同成长规则，抽取权重仍不变。
- 每条 `/出招` 最多处理 32 个实际招式，超过时保留游标并提示再次 `/出招`。
  这是事务/图片分片，不截断连锁、不封顶核心、不强制换成普通招式。

| 应急绷带 | 纤维4、零件2、补给3 | 本场首次重伤正数招式免该招的 -1；不治疗、不降风险 |
| 入场彩纸 | 纤维2、补给1 | 入场卡庆典装饰，无战斗数值变化 |

绷带免除的是公式内伤势项，该招若有贷款则按修正后的基础值翻倍；不是另发数值奖励。
每方入场前至多选择一种，接受时预留一件，真正触发才记为消耗；终局未触发退回，
包括认输和超时。彩纸在正式入场时触发，待接受邀请不消耗。暂不引入第四轮成就专用券。

## 5. 败者战利品

- 仅自然抽中“力竭倒下”的败者获得额外抓猪；Ruleset45新场为三次，不占正常额度，没有额外经验或抓猪猪币。
  不自动发动群术式、复制、自动赠送或美食奖励；不记普通抓猪次数、普通抓取价值或本周价值榜。
- 新版基础 1–6 星分布：**5%、10%、10%、30%、30%、15%**。仅叠加**败者**永久等级、
  饲料和猪果冻云冻的永久层数，复用既有单调加权逻辑；胜者永久成长不介入。
  没有授权六星池时六星概率归入五星；周四 KFC 限定继续按业务时区判断。
- 临时道具、美食、群级六星效果、术式不会参与，也不会减少剩余次数。
  结果图展示本次最终概率、永久来源、本场剩余次数、实际捕获者、接收者昵称和猪的图卡。
- 生成猪、胜者图鉴、成功交付事实、次数与消息回执在同一事务提交；只更新实际接收者图鉴。
  现有成就采用明确的战利品来源，不能把它再当普通捕获；新战利品成就第四轮另接。
- 自动入口与普通抓猪使用相同命令名、参数指纹和消息幂等键；一条消息只能落一类回执。
  已经提交的普通抓猪在后来出现战利品后仍重放原猪，不会被重复消息改写；旧手动入口使用独立
  命令键，但与自动入口原子消费同一 FIFO 次数。
- 未用次数跨天、跨抓猪时段、跨重启保留，不设置过期。多场按完成时间领取，
  同秒按本群单场顺序的单调场次号处理，不按随机 B 编号排序。
- 与普通抓猪共享冷却；管理员临时抓猪硬限额仍可拦截，避免靠额外次数绕过处罚。
- 双方配置黑白名单、插件封禁、赠送/收赠封禁、交易封禁和有效自动监管限制都重新核验。
  后来被限制时暂停交付，剩余次数不删除；解除限制后可继续。管理员只豁免自动监管，
  不因此绕过手动黑名单。对战不会读取聊天正文或猜测小号。

## 6. 保护、事务、恢复与版本化

- `battle_protections` 防误处置，`asset_occupancies(purpose='battle')` 防同时活动。
  设置过或升级过的战斗猪默认保护；单只/批量做菜、售卖、赠送、交易与管理员移除均不可绕过。
  SQL 触发器兜底，背包与详情显示“战斗保护”。收藏、乐队保护与战斗保护相互独立。
- 空闲保护猪可以参加派遣；活动中的猪不能同时派遣、巡演或对战。解除战斗保护必须确认，
  不删除强化、不清收藏、不清乐队保护。转入有强化的猪自动恢复新主人的战斗保护。
- 所有写操作在 SQLite 同一即时事务内完成，含材料/猪币/器具账本、角色额度、状态、随机结果、
  保护与回执；跨连接并发接受只有一次成功。回执重放复用原结果，失败不重抽、不多扣费。
- `battle-v1` 目录与纯规则、仓储、应用服务、命令和图片分层。随机种子不出现在玩家图片或文字中；
  SHAKE256 按场、回合、玩家侧与序号分域确定抽样，整数拒绝采样避免浮点累计权重失真。
- 累计权重和核心使用任意精度整数；大于 63 位的持久化值用带标记十六进制 JSON 表达。
  读取对战快照须用 `domain.battle.loads`，不修改全进程整数字符串限制。已测试 5001 位权重。
  卡片对超大值缩写展示，胜负仍按完整整数抽取。
- 未来更改规则需保留旧版本解码/执行或明确迁移；未知规则版本拒绝继续抽样，不能套新轮盘重算旧场。
- 两个普通 QQ 群和两个官方 QQ 群复用同一实现，但身份、材料、额度、场地、战利品严格按精确 scope 隔离。
  本轮没有更换素材、引入真实成员资料或修改两个官方适配器。

Schema 39 增加 13 张表，旧表旧行不改写：

| 类别 | 表 |
| --- | --- |
| 伙伴与培养 | `battle_profiles`、`battle_training`、`battle_protections`、`battle_upgrades` |
| 器具及账本 | `battle_tools`、`battle_tool_ledger` |

关键索引/触发器参与启动完整性校验；自然终局发放、逐次交付归属和不可变历史另有数据库约束。
不会删除对战历史来腾出群槽位，历史分页读取。关闭插件不清除未完成场次。

## 7. 第四轮成就事实接线契约

`activity_facts.system='battle'`，版本为 `BATTLE_VERSION`，使用稳定玩家/场次/子事件键幂等写入：

- 双方邀请/入场、每次出招数、逐招基础/强化/核心/伤势/倍率/借招/余招、回合胜负、实际伤势盘、
  状态前后快照、自然或非自然终局均有实际业务记录，不能用发命令次数代替达成。
- 单招实际所属玩家单独记账；回合、终局以及战利品交付向两个参与者分别保存角色标记。
  入场时 `core=0`，核心不继承上局；自然终局事实明确 `natural_end`。
- 养成事实含本人付款、猪实例、前后等级、费用和支付前本人累计自然矿石流入。
  自然矿石统计只含派遣基础/普通加成/自然奇遇，不含转换、赠予或未来成就补发。
  该字段是历史自然产出证据，**不是声称背包能区分每一块矿石的来源**；第四轮据定义核验本人全程培养。
- 战利品以 `battle_id + ordinal` 精确引用实际行动者、接收者、猪实例及已提交成功交付，
  获得机会不等于已完成全部交付。成就按该场保存的 `total_uses` 判断，旧五次场与新三次场均可达成。
- 本轮仍是旧 **82 项**成就目录与固定 **49 项**常规毕业；不偷跑新增 48 条、奖励券、外观或重新定义周榜。
