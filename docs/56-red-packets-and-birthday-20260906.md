## 玩家红包

- `/发红包 1000 10 祝大家好运`：从发起人余额扣1000猪币，拆成10份拼手气红包。
- `/抢红包`：抢本群最新的未结束红包，每人对同一红包只能抢一次。
- `/抢红包 红包编号`：指定较早的红包；10位红包编号与资产编号是不同命名空间。
- `/红包 [红包编号]`：查看剩余份数、猪币、领取榜与领完后的手气最佳。
- `/猪管发红包 9600 20 生日快乐`：仅插件管理员使用，由系统出资，不扣管理员余额。
- `/抓猪帮助 红包`：规则与可复制命令；`/猪管帮助`包含系统红包说明。

总额1～1000万猪币、1～100份、每份至少1币；每位发起人最多10个未结束红包。
普通包扣款时把猪币转入托管，领取使用有界二倍均值整数抽样，最后一份取剩余全部。
红包24小时有效，普通包余款自动退回；系统包未领部分直接到期，不给管理员退款。
不收交易税、不占猪/菜赠送次数；不是押注或双方赌币。原有插件访问限制继续生效。
猪/菜赠送与交易黑名单仍只管理其原有资产转移业务，本轮没有扩大处罚范围。
只在同一群作用域发送和抢领，普通用户不能伪装成系统发包。

`red_packets`记录资金来源与余量，`red_packet_claims`以红包+玩家联合主键防止多领。
扣款/领款/退款均写入原猪币账本，业务、审计、回执共用一个SQLite立即事务。
同一消息重试返回旧回执；参数不同拒绝，不重新抽签，不重复扣/发币。
发包、抢到、详情使用红金主题图片；渲染异常才发送已提交的文字结果。

## 运维入口

仅在正式升级完成后使用（不会自动迁移旧数据库）：

```powershell
uv run python tools/operate_social_rewards.py --database '<实际数据库路径>' status
uv run python tools/operate_social_rewards.py --database '<实际数据库路径>' schedule --scope '<平台:群ID>' --confirm-commemorative
uv run python tools/operate_social_rewards.py --database '<实际数据库路径>' run-due
```

`schedule`必须一次列出所有目标`--scope`，重复执行同参数安全，改参数拒绝。
`run-due`不能提前发放，只补未提交事务，不负责群消息（由在线插件处理持久化公告回执）。
运营脚本默认不发奖：必须显式选择schedule或run-due；status只读。
