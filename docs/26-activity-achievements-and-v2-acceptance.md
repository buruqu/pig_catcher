材料选择先预览，30 秒内确认，过期不扣库存。每个自选份只兑换 **1 份**材料；

这些奖励和兑换不计入派遣“自然产出”，不能赠送、收赠或交易。
`/成就奖励 确认` 独立于吃菜 `/是`，也不覆盖派遣、巡演、战斗的确认单。

## 3. 专用券实际规则

| 券 | 生效时机与效果 | 消费和互斥 |
| --- | --- | --- |
| 远行路费券 | 下一次付费派遣确认出发，最多减免 120 猪币 | 免费路线不扣；与行李券同一个数值槽 |
| 口袋行李券 | 下一趟正常完成且至少 4 小时的派遣，平加 3 份路线主材料 | 确认出发时扣；召回不退，不随队伍倍率放大 |
| 旅行惊喜券 | 为下一趟合格正常返程追加一段原创旅行纪念 | 视觉槽独立；不加奇遇概率，不冒充自然纪念品 |
| 巡演档期券 | 立即补 1 张档期 | 仍最多 7 张；满额不扣 |
| 安可稳场券 | 下一次正式站点的负波动修正为 0，最多挽回 3 分 | 不重抽、不保证 SS；已有器具修正过的部分不重复补偿 |
| 安可留影券 | 开演绑定，完整完成三站后追加一张原创返场合影记录和结算卡内容 | 与稳场券独立；放弃未完成巡演不补三站奖励 |
| 训练热身券 | 下一次本人成功强化最多减免 300 猪币 | 材料照付，初次强化可免猪币；不改五级上限或招式增量 |
| 整活入场券 | 双方正式应战时生成本人原创入场海报 | 邀请、拒绝、过期不扣；初始胜利权重仍为 5 |

同槽重新选择会替换待命券，不会立刻扣券。选中一张只负责下一次操作，库存里其余同名券
不会自动连吃。预览、确认及实际使用结果显示券名、效果、库存或消耗后的剩余张数。
选择变化会使旧预览失效；资源不足、归属变化或业务回滚时不会单独吞券。

## 4. 判定口径和可靠性

- **派遣**：正常完成和提前召回分开；并行旅行时间取并集；奇遇材料不在完成时再计一次；
  同批三队按实际开始时间、队伍和路线判断，不按返程消息相邻与否判断。
- **巡演**：逐站检查当时成员、主题、成绩与高光，不拿最后一站代替全程；美咲/米歇尔规范身份
  与不同形态各有正确口径；联演只有明确接受且双方各完成三站才计合作伙伴。
- **对战**：出招、贷款、零招、核心、伤势先暂存，只有自然完成才计相关条目；邀请、拒绝、超时、
  认输不能刷自然完成数。五次交付仅计实际抓取并交付的败者，不把胜者收货当作本人完成。
- **本人养成**：使用本人累计有效贡献和实际支付事实，不因收下别人练好的猪就追认全部养成。
- **跨玩法**：矿石与舞台组件检查自然来源，训练/设备支付和后续参与有先后顺序；同行猪须是同一实例。
- **隐藏条目**：名字、精确条件、进度分母、奖励和外观在未解锁前遮罩，解锁后再揭晓。
- **玩家和群**：普通 QQ 与官方 QQ 的四个精确 scope 都走同一代码，但进度、材料、奖励、券和身份不合并。

已修复旧成就猪币奖励的全库去重键缺少玩家的问题：现在包含 `player_id`（其内已有 scope）。
多人或多群达成同一成就不再互相冲突。旧解锁记录仍是领取依据，不重写历史账本，也不会因换键补发第二遍。
新奖励产生的正常猪币收入可在本次结算中继续触发旧财富成就；固定点循环有上界，去重后不会自循环发钱。

业务先提交，再由成就消费者另开原子事务处理进度、解锁、点数和奖励。成就失败不会回滚或重抽
已经完成的派遣、巡演、战斗；原始事实和待处理队列仍在，后续相关操作或成就查询可继续处理。
未知事实版本拒绝消费，不猜测隐藏条件。

## 5. 数据和扩展入口

Schema 40 仅新增五张表及相应约束、索引：

| 表 | 用途 |
| --- | --- |
| `achievement_activity_queue` | 事实触发器入队，提交顺序、历史标记、处理完成点 |
| `achievement_activity_state` | 按玩家保存小型条件投影，不复制全部事实或图片 |
| `achievement_coupon_selection` | 玩家各用途槽的待命券 |
| `achievement_coupon_uses` | 不可变、按业务来源唯一的使用和剩余库存记录 |
| `achievement_material_choices` | 玩家独立的 30 秒材料兑换确认 |

主要入口：

- `domain/data/activity_achievements_v1.json`：正式运行目录、奖励注册表、固定集合。
- `domain/activity_achievements.py`：验证并生成定义；与仅供设计的 JSON 分离。
- `domain/activity_progress.py`：无 I/O 的派遣、巡演、对战与跨玩法 reducer。
- `services/activity_achievements.py`：队列消费、补录、定点发奖与原子重试。
- `services/achievement_rewards.py` / `repositories/achievement_coupons.py`：材料选择与分用途券。
- `rendering/cosmetics.py`：原创外观注册表；图卡模板复用原渲染/发送队列。

后续增加条目使用新稳定 ID；普通阈值或固定集合可追加数据，复杂条件需补 reducer 和事实证明测试。
已颁发目标不原地加难；新集合应单独冻结版本。原始事实仍保留，未来补算须审核版本和证据，
不能把开发测试记录导入生产，也不能只改中文描述就宣称增加了玩法。

迁移入队的旧活动事实走个人历史汇总，不由第一个发命令的人替全群广播全部旧成就。
当前生产尚无新三系统真实事实；正式上线时新成就从真实活动开始，旧 82 项仍按原可靠历史回填。

## 8. 上线前仍需用户安排的门禁

1. 批准读取最新生产数据库的克隆，在隔离环境再做真实数据规模的迁移、资产和经济核对。
2. 约定测试机器人/测试群，验证 QQ 实际消息、双人交互、图像发送与重试；本轮未连接真实 QQ。
3. 用户验收并批准维护时间，停写、取最终备份、迁移、切换版本后再开放。
4. 需要回滚时恢复维护前快照和旧代码，不能让旧代码直接打开 Schema 40；开放后的新业务另按事故方案处理。
