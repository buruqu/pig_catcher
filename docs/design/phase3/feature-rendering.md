## 展示接口

`pig_catcher/rendering/feature_art.py` 提供四个 Jinja helper：

- `feature_icon(key)`：62 个白名单原创 SVG 形状。使用真实道具 ID／名称匹配；未知名称只回退中性回执图标。标签不能解释为 SVG 或文件路径。
- `feature_scene(key)`：五条派遣路线与五个巡演舞台；没有对应场景时返回空，不补造地点。
- `feature_wheel(segments, selected_index=None)`：静态比例扇区，仅展示给定权重。限制 1—16 个选项、有限正权重、有限标签长度；没有明确结算记录时不画“已抽中”标记。
- `feature_backdrop(family)`：只允许六个本地母版族。读取不超过 1600 万像素的母版，派生为不超过 960×360、256 KiB 的 WebP；母版不改写，有界缓存。

`clear_feature_art_cache()` 可在卸载和显式清理时释放背景、图标、场景缓存。先缩小再转换 RGB，并显式释放中间图片；装饰母版损坏时只省略装饰，不阻断已提交的业务卡片。主题 CSS 由统一 renderer 加载；组件定义在 `feature_components.html`，不在每个模板复制完整 SVG。

### 仅新增展示字段

- `DispatchView.presentation` 标识派遣／道具背包／外观回执，旧 JSON 没有字段时按派遣解码；`scene_key` 仅用于路线、舞台标识。
- `TourView.from_payload` 保留上述字段，旧回执仍可解码。
- `BattleView.wheels` 记录公开的轮盘卡信息。规则页没有选择；实际出招、失败回合使用已经存储的抽签结果。
- 对战回合抽签采用 `round_result.before` 的伤势和借贷条件，不能用抽到核心后的恢复状态去改画先前的出招盘。
- `GroupEventViewModel.assets` 是已提交的真实资产投影，包含编号、品质、归属、可见性和动画标记。茈不再只显示前三只；领域双份出餐逐份显示归属。
- `GroupEventViewModel.roulette_outcome` 仅由真实轮盘结果填写。开盘资格图只显示规则，不显示虚构停靠面。

## 数据与隐私边界

美术 helper 不读取玩家库、不写账、不访问网络、不拥有随机源。不存在“为了出图再抽一遍”的路径。实际结果由业务服务先提交，再交给图像层；图片失败不能重做业务。

群事件新增资产投影会隐藏不在当前作用域开放的原名／素材；昵称采用现有安全展示回退，不能把原始 OpenID 当作群友昵称。模板不能从隐藏的奖励条件推导彩蛋说明。

多资产图片映射只用本次回执的短编号，不扫描整个素材库。标题、数值、效果说明、指令保持正常文档流；不会为了卡片高度截掉最终概率或剩余次数。

### 结果卡与佩戴陈列室的最后一组视觉专项

- 提示修正后的 `pytest tests/test_item_bag.py -q` 为 61 项通过；新增断言保证引导指向已注册命令。
- 12 份输出没有文字裁剪、元素越界、坏图、正文重叠或异常垂直留白；全图及 320px 缩略均已目视。320px 下优先保留名称、概率与外观识别，长段效果须打开全图阅读，没有删掉尾部文字。
