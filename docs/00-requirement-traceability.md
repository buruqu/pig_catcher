# 需求来源与追溯矩阵

## 1. 输入来源

本轮设计基于：

- 用户提供的《抓猪插件.txt》初步构想。
- 四张同类收集插件截图，仅用于分析信息层级和展示场景。
- 本机 MaiBot `1.0.12`、`maibot-plugin-sdk 2.7.x` 和现有插件开发规范。

截图中的水母题材、深蓝背景、素材、文案、具体卡片与排行布局均不属于本项目需求，也不进入后续资产。

## 3. 派生工程需求

以下并非对原构想的照录，而是为了完整、安全实现而补充：

| 编号 | 派生设计 | 原因 |
| --- | --- | --- |
| D-001 | 所有玩法使用显式斜杠命令 | 避免监听普通消息和误触发 |
| D-002 | 同名实例使用 `名称#短编号` | 防止做菜、售卖和交易误选 |
| D-003 | 做菜默认消耗原料猪 | 与“用猪做菜”的资产语义一致，仍列为待确认 |
| D-004 | 交易采用报价、接受、拒绝和过期 | 防止未经对方确认直接扣币 |
| D-005 | 不可变猪币账本 | 支持对账、审计和并发安全 |
| D-006 | 消息幂等收据 | 防止适配器重投导致重复资产和转账 |
| D-007 | 业务提交与图片发送分离 | 图片故障不破坏已完成结算 |
| D-008 | 平台与群组成数据范围 | 防止 6 星素材和资产串群 |
| D-009 | 6 星素材授权、撤回和占位替换 | 保护群友素材隐私与可撤回性 |
| D-010 | 随机规则版本与落点快照 | 便于概率争议复核和数值调平 |
| D-011 | SQLite 迁移、备份和重启恢复 | 支持长期运营和版本升级 |
| D-012 | 冷却与每日次数 | 防止刷屏和经济快速通胀，数值仍可调整 |

## 4. 参考图分析结论

可借鉴的信息组织：

- 单次详情突出主体素材和三个核心属性。
- 背包需要进度、筛选、数量和稳定网格。
- 图鉴按品质拆分，并明确未收集状态。
- 排行榜在群聊中优先展示前十和关键统计。

必须形成差异的部分：

- 深蓝改为白色、淡粉结构和多品质点缀色。
- 水母图标和题材全部替换为用户后续提供的猪与美食素材。
- 不沿用其外层面板、内层卡片、胶囊筛选器和排行行样式。
- 单次结果改用“称重证书”，商城与交易改用“粉色票据”，图鉴改用“收藏索引册”。
- 不复制参考图中的任何文字、数值、名称和装饰。
