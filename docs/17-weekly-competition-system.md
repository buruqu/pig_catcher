# PiG Dream! 周冲榜机制与第一期实现记录

> 开发状态：`2.0.0.dev2` / Schema `36` / Ruleset `31`，位于 `develop/2.0` 隔离开发线，
> 尚未部署、启动或连接正式 MaiBot。

## 1. 第一期活动

- 期数：第 1 期
- 名称：**抓猪冲刺！！！**
- 指标：本周成功抓到猪猪的累计官方价值
- 周期：北京时间周一 `00:00` 至下周一 `00:00`
- 范围：当前精确 `platform + group_id`
- 查询：`/抓猪线 [页码]` 或 `/zzx [页码]`

只有正常 `/抓猪` 成功事务中的主猪实例计分。复制猪、管理员发放、成就纪念猪、术式附带产物
和其他非抓猪来源均不计分。每条成绩绑定不可变业务回执；猪猪之后被售卖、赠送、交易或做菜，
历史成绩仍然保留。

## 2. 排名与展示

榜单以累计官方价值从高到低排序。同分时依次比较：

1. 单只猪最高官方价值；
2. 本期有效抓取数量；
3. 达到最终成绩的时间，较早者优先；
4. 稳定玩家 ID，仅作最后的确定性排序。

每页固定 10 人。榜单显示期数、名称、状态、北京时间周期、剩余时间、总参赛人数、本人名次、
累计价值、抓取数和单只最高价值。前三名使用克制金银铜视觉，4 至 10 名使用淡粉账簿行；无成绩、
活动进行中和已结算都有独立状态。昵称优先使用当前群显示名，稳定身份不作为普通用户展示名。

即使活动定义调整，也不会改写已经结算的玩家奖励。

## 4. 结算、补录与故障边界

- 活动首次启用会从本周周一开始扫描已提交抓猪回执并幂等补录，不要求功能恰好在周一上线。
- 正常抓猪提交后增量写成绩；榜单处理异常不得回滚或重复玩家已经完成的抓猪事务。
- 活动结束后的首次查询或业务触发先补录，再按精确群结算前十。结算、账本、库存和待通知记录
  在同一数据库事务完成。
- 成绩表按活动与抓猪回执唯一；结算按活动与群唯一；奖励同时约束玩家和最终名次唯一。
- 图片生成或发送失败只切换为文字降级或保留可重试通知，不能重新结算。领取发送权后进程退出的
  状态会在 10 分钟后自动恢复；个人奖励卡只成功投递一次，奖励资产始终只结算一次。
- 第一期开启后会把规则固化为活动快照；活动结束后冻结，不自动创建第二期。

## 5. 数据驱动扩展

活动定义声明业务来源、指标字段、聚合方式、排序方向、显示单位和奖励档。底层已支持
`sum`、`max`、`min`、`count` 与升序/降序，因此后续“最重猪”“最轻猪”“六星数量”或特殊主题
可以作为新定义接入，继续复用相同的分页、同分排序、结算、奖励、通知和渲染管线。

每一期仍需明确名称、统计事实、有效范围、同分口径和奖励后再登记，避免系统在没有运营方案时
自动复制上一期活动。

自动测试覆盖：第一期定义、北京时间周界、历史回执补录、稳定同分、资产离开背包后保分、精确
群隔离、重复处理、前十奖励、第 11 名无奖励、猪币账本幂等、通知一次、活动外观佩戴、插件抓猪
增量计分、两个命令入口和图片渲染。正式上线前仍须使用最新生产数据库克隆执行 Schema 34→36
迁移、周一切换并发、规模性能、主要图片人工验收和完整回滚彩排。
