## 2. 玩家操作

以下是开发线的命令。正式群暂不可用；猪名请替换为自己背包中的猪。

```text
/猪猪派遣 路线
/猪猪派遣 编队 1 口琴猪、特小猪、大象
/猪猪派遣 确认
/猪猪派遣 出发 1 回声矿洞 8小时
/猪猪派遣 确认
/猪猪派遣
/猪猪派遣 返程
/派遣背包
/派遣游记 1
```

编队确认只保存队员，不收钱、不占用。出发确认才一次扣旅费和器具并占用猪；
预览有效期两分钟，同群同玩家只保留最后一项。重复旧消息只重放旧结果，不替换新的待确认内容。
取消使用 `/猪猪派遣 取消`，不会取消已经出发的旅行。`/是`、`/否` 仍专用于吃菜确认。

| 功能 | 指令 |
| --- | --- |
| 可复制帮助 | `/猪猪派遣 帮助` 或 `/抓猪帮助 派遣` |
| 清空空闲队伍 | `/猪猪派遣 编队 1 清空`，再确认 |
| 提前召回 | `/猪猪派遣 召回 1`，再确认 |
| 全部器具配方 | `/派遣背包 配方` |
| 制作同名器具 | `/派遣背包 制作 区域地图 2`，数量 1–99 |
| 基础材料转换 | `/派遣背包 转换 训练矿石 灵巧纤维 2`，扣 6 矿石得 2 纤维 |
| 单趟历史 | `/派遣游记 D开头的旅程编号`，编号从返程图复制 |
| 纪念品册 | `/派遣游记 纪念品 1`，共 3 页 |
| 查看罗盘候选 | `/派遣奇遇` |
| 选择罗盘候选 | `/派遣奇遇 旅程编号-块号 1`，末尾选 1 或 2 |

名字直选取最低价值、未收藏、未交易、未被活动占用的同名猪。重复写同名猪会逐个选不同实例。
想带收藏猪，使用完整 `猪名#编号`；预览会显示收藏状态，明确确认后才出行，返程收藏不变。
禁止改队、跨队重复占用同一只猪；已保存但尚未出发的队伍只是计划，不锁资产。

## 3. 数值与费用

| 路线 | 主材料 | 特长 | 适配方向 | 每四小时旅费 |
| --- | --- | --- | --- | ---: |
| 青草近郊 | 旅行补给 | 后勤 / 搜寻 | 本品种较小体型 | 0 |
| 回声矿洞 | 训练矿石 | 搬运 / 采掘 | 本品种较高体重 | 20 猪币 |
| 废旧工坊 | 机关零件 | 机械 / 研究 | 本品种较小体型 | 20 猪币 |
| 风铃林地 | 灵巧纤维 | 灵巧 / 探路 | 本品种较小体型 | 20 猪币 |
| 旧舞台仓库 | 舞台组件 | 音乐器材 / 交涉 | 本品种较高体重 | 20 猪币 |

- 每队 1–3 只，至少一只 1–3 星、最多一只 4–6 星；单/双/三猪效率为 40%/70%/100%。
- 时长 4/8/12/24 小时，从确认出发时刻起算，不跟随抓猪时段刷新。
- 满编每四小时基础为 6 主材料 + 2 补给。近郊两者合并为 8 补给，不重复领取。
- 加成相加：全低星 +10%；两项地区特长各 +5%；相对属性最多 +5%；平均熟练等级每级 +1%。
  总上限 30%；星级、售价、绝对吨位不会额外加成。
- 熟练度 0–5，累计有效时长 12/36/72/120/192 小时晋级；进行中的旅程使用出发快照。
- 有效派遣累计 12 小时开第二队，72 小时开第三队。多队重叠时间取并集，不叠加人数或队数。
- 材料按 `1 份 = 10,000,000 单位` 保存零头；取整后的份数可用于制作，零头继续累计。
  同快照下六次四小时与一次二十四小时总量一致。分段出发期间自然升级熟练度是合法的成长差异。
- 旅费出发时一次性支付；余额不足整笔拒绝，可去免费近郊。已出发后召回不退旅费或器具。

派遣不消费普通抓猪额度、抓猪/做菜道具、任何菜品效果、术式资格或六星菜专属次数。
不发经验或猪币，不计入首期“本周抓猪价值”；材料不能转赠、交易或出售。

## 4. 奇遇与器具

每四小时增加 0.4/0.7/1.0 探索单位，同玩家同精确群同地区共享。每满一单位判定一次，
基础 10%；连续九次未中，第十次强制命中。加成不额外增加探索次数，标签只影响奖励分支。
无关捕获概率、猪星级和抓猪时段。一次命中后重新累计未中次数。

区域事件分材料、手记、纪念品、配方成品、故事五类；基础分支权重分别 4/2/3/1/1。
同时覆盖地区两项特长时，手记与纪念品各加 1 权重。材料分支额外给 1–3 份，手记给 1 份；
纪念品每区四件，重复转 2 补给。配方分支附赠一件可直接使用的器具，不发空壳道具。
罗盘第二候选由同一已固定随机位置确定，且与第一候选属于不同分支；不是再抽一次奇遇。

| 器具 | 制作成本 | 出发参数与效果 |
| --- | --- | --- |
| 区域地图 | 3 补给 + 1 零件 | `区域地图 训练矿石`：返程最多把本趟 4 份通用补给等量转换为指定基础材料；不动近郊主产物，支持不足一份的零头 |
| 纪念相机 | 4 补给 + 2 纤维 | `纪念相机`：命中纪念品分支优先本区未拥有项，不额外保证奇遇 |
| 奇遇罗盘 | 8 补给 + 4 零件 + 1 手记 | `奇遇罗盘 2`：本趟首次奇遇给两个固定候选，末尾是自动选择偏好，默认 1 |
| 整理箱 | 2 补给 + 1 零件 | `整理箱 机关零件 20 训练矿石`：返程把库存超出保留 20 的零件按整数 3:1 整理；包括已有库存，不是增产 |

器具放在出发命令的时长之后，每趟只带一件。材料转换数量指最终得到的数量，只有四种基础材料
允许 3:1 互转，补给与手记不参与。制作、转换与重复消息均原子且可对账。

罗盘待选不锁猪、不延迟其他奖励。候选会保存在数据库；下一次出发前仍有未选项，
按各趟出发时保存的偏好自动领取，并在新出发图提示处理数量。不能靠不领取积攒无限新选项。

## 5. 结算和资产保护

没有每猪定时器、后台高频轮询或全库玩家扫描。相关命令先在当前事务内推进该玩家的到期时间块，
最多三趟、十八块；按块结束时刻和旅程序号排序。猪未到期时不发材料，正常结束或召回才入账。
整块产生的有效时间和保底状态可先推进，未满四小时部分不算。长期离线回来一样结算，不会重复出发。

到期后，查询背包、做菜、出售或赠送等相关操作也会先完成结算并释放占用，不要求先 `/猪猪派遣 返程`。
返程命令仅合并显示最多三条未读结果；历史奖励和游记没有领取截止日。召回只保留已完成整块，
确认刚好遇到自然到期时仍算正常完成，不倒改成召回。

所有忙碌判断在自动选择/批量保留排名和 `LIMIT` 之前进行。精确点名忙碌猪会收到清楚提示，
不是偷偷换另一只。数据库触发器再次禁止忙碌猪被消耗、转移、锁进交易或物理删除。
未收藏同名实例按既有规则选择；不会把派遣锁误算成普通收藏而破坏原来的保留规则。

## 6. 数据和代码入口

| 层 | 入口 / 职责 |
| --- | --- |
| 纯规则 | `pig_catcher/domain/dispatch.py`：路线、配方、产量、保底、确定性随机与故事；`domain/data/dispatch_specialties.json`：173 模板特长 |
| 命令 | `pig_catcher/commands/dispatch.py`：严格解析；`plugin.py` 四个显式命令，仅接线和交付 |
| 数据库 | `infrastructure/migrations/v0037_dispatch.py`：14 张新表、索引、不可变账本/事实和占用保护触发器 |
| 仓储 | `repositories/materials.py`：余额与对账；`repositories/dispatch.py`：逐块结算、工具、保底和事实；`activity_locks.py`：公共忙碌检查 |
| 服务 | `services/dispatch.py`：快照、确认、事务和回执；`dispatch_queries.py`：页面投影 |
| 图片 | `domain/dispatch_views.py`、`rendering/templates/dispatch.html`、`render_dispatch`：结构化图片与同源文字 |
| 测试 | `tests/test_dispatch.py`、`tests/test_dispatch_plugin.py`；`tools/accept_dispatch_views.py`：可复现离线图卡验收 |

Schema 37 只增加数据结构和保护触发器，不改写旧表数据或正式素材。当前版本快速启动同时核验新表、
关键索引与触发器，不接受“只有版本号正确、保护实际缺失”的数据库。材料账本与活动事实不可更新或删除。

范围严格为 `platform + group_id + player_id`。两个普通群及其对应两个官方群共用定义但不合并数据。
本人培养时长与猪实例总熟练度分开：转让不抹掉猪的熟练度，但不会把前主的培养算作新主培养。
历史/回执图片按当前媒体授权再遮罩；群昵称用于展示，OpenID、随机种子和内部审计身份不进入图片文字。

后续扩展应修改独立定义与有名处理器，不能在命令里堆猪名判断。`definition_version=1` 已写入出发
快照；未来改规则必须支持或显式迁移旧旅程，不能简单替换常量让在途旅程按新产量重算。

## 7. 第四轮成就接线契约

`activity_facts` 使用 `player_id + source_type + source_id + subevent_id` 唯一，保存定义版本、
逻辑发生时间和完整快照。出发、每个整块、每次奖励、正常结束/召回、制作和转换分别记录。
晚处理的正常返程同时保留计划结束、逻辑结算和实际处理时刻，不把“晚领”变成晚结束。
奇遇保留旅途中的逻辑发生时间，奖励账本和纪念品获取时间使用实际返程/召回的入账时刻，
通过 `credited_ms` 明确区分，不能把尚未入包的材料记成提前获得。

- 基础产出 `dispatch-base`、普通加成 `dispatch-bonus`、自然奇遇 `dispatch-encounter`、
  重复纪念品 `dispatch-souvenir-duplicate`、器具转换 `dispatch-tool-conversion`、
  制作 `dispatch-tool-craft`、普通转换 `material-conversion` 有不同来源。
- 每块事实保存基础/加成单位、人数与出发快照引用、探索和未中次数前后值、实际随机值与强制保底标记。
- 完成事实保存成员实例/模板/星级、器具、属性/特长/熟练度快照、正常或召回、起止及完整块数。
- 三队合并显示不合并事实；实际出发时间可识别 15 分钟内的同批次，个人实例贡献可识别亲手培养。
- D11 的“特小猪”是既有二星模板，不按本次尺寸猜身份；其他条件由第四轮读取稳定模板 ID。

第一轮不注册这 48 项成就、不发新券；当前目录仍 82 项，旧 49 项毕业不变。新事实留作后续投影，
在可靠消费/归档方案完成前不得按普通缓存清理。开发验收数据不能导入生产发奖。

## 9. 交付边界与下一轮

本轮只提交本地 `develop/2.0` 源码和文档，不推送、不打正式发布标签、不发公告。
巡演、战斗、48 项新成就仍按后三轮开发；生产克隆规模测试、真实 QQ、最终数据迁移和回滚彩排
属于 2.0 的整体发布门禁，不能用本轮合成离线验收代替。

运行缓存继续使用既有有界图片/发送队列。派遣不增加常驻任务，每次推进有三队十八块上限，
历史每页六趟、纪念品每页八项、返程最多三趟、待选奇遇最多三项；未读返程有部分索引。
保留不可变材料与事实的存储成本是审计需要，第四轮完成投影后再设计可验证归档，不能先删记录省空间。
