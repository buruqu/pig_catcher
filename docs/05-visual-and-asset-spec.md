# 视觉与素材规范

## 1. 设计立场

参考图只用于确认信息需求：

- 单次获得需要突出素材、品质、名称、属性、价值和新纪录。
- 背包需要同时表达筛选、数量、关键属性和分页。
- 图鉴需要区分已收集、未收集和各品质进度。
- 排行榜需要让名次、展示物和统计在群聊缩略图中仍可辨认。

新插件不复刻参考图的水母主题、深蓝背景、面板边框、卡片比例、装饰符号和具体排版。新视觉采用独立的“白色收藏册与淡粉称重票据”语言，整体轻盈、明亮、有一点群聊整活感，但不能牺牲可读性。

## 2. 视觉关键词

- 白色收藏册
- 淡粉票据
- 称重印章
- 清爽图鉴
- 轻松但不幼稚
- 稀有品质有辨识度，普通信息保持安静

避免：

- 大面积深色背景
- 单一粉色覆盖所有信息层
- 多层卡片嵌套
- 过度圆角、发光、玻璃拟态、渐变球和无意义装饰
- 把文字压在复杂素材上
- 为追求可爱而降低对比度

## 4. 排版与组件

- 中文字体优先使用可随插件合法分发的开源 CJK 字体；系统字体只作后备。
- 标题、名称、正文、数据使用明确的四级字号，不用随视口宽度连续缩放字体。
- 字距固定为 `0`。
- 圆角不超过 8px；只有图片裁切、单个物品单元和真正的回执区域使用边框。
- 页面分区优先使用留白、细线和浅粉色横带，不把整页切成层层悬浮卡片。
- 数字使用等宽数字特性，体型、重量、价值和排行分数右对齐。
- 状态图标使用 MaiBot 或现有图标库中的标准图标；不手绘替代常见图标。

## 5. 渲染模板

### 5.1 单次抓取

采用竖向“称重证书”：

1. 顶部为品质、猪名、获得者和时间。
2. 中部为完整素材，保持主体可见，不做过暗或过度裁切。
3. 下部为称重票据，横向展示实际体型、实际重量、直观体态和价值，不展示内部百分位。
4. 底部显示猪币、经验、图鉴状态和纪录结果。
5. 新纪录使用独立印章位，不通过全页发光表达。
6. 首次收集显示独立 `NEW` 标记；迷你、巨型或极端个体显示一条体型评价。
7. 达到绝对体型或重量门槛时显示“全群纪录”和“巨物目击”标记。

建议尺寸 `1200 x 900`，素材安全区至少 `640 x 430`。

### 5.2 猪猪与美食背包

采用“收藏册展开页”：

- 顶部单行显示用户、余额、等级、筛选和页码。
- 主体固定四列，单元尺寸稳定，长名称换行而不挤压图片。
- 每个单元只显示素材、品质、名称、短编号和一种当前排序指标。
- 页面底部显示总数、总价值和翻页提示。
- 详情信息通过详情命令查看，不在一个小单元里堆满所有数据。

建议宽度 `1200`，每页最多 12 项，高度由行数限定在 `900..1700`。

### 5.3 图鉴

采用“索引册”而不是背包复制：

- 每个品质使用整行标题带和收集进度。
- 已收集条目显示素材和最佳纪录；未收集条目显示统一剪影与编号。
- 当前群已授权但未发现的 6 星条目只显示保密占位，不显示姓名、轮廓或描述。
- 未授权群不显示其他群的专属条目，也不把它们计入图鉴总数。
- 图鉴不分页；当前筛选的全部条目按一至六星顺序输出到一张完整长图。
- 使用五列紧凑稳定单元和独立品质标题，在完整展示的同时控制高度与发送体积。
- 完整正式库必须以 83 只猪、19 道美食规模检查裁切、坏图、非空像素和 PNG 大小。

### 5.4 美食结果

采用“厨房出餐单”：

- 原料猪以小型来源章展示。
- 成品素材是视觉主体。
- 品质、菜名、偏肥瘦类型、份量、价值和效果明确分区。
- 品质名称与星级必须是第一视觉层级，高于实例编号和技术媒体信息。
- 展示厨具和本次消耗品加成，但不显示冗长概率计算。
- 6 星结果可使用更丰富的分段边线，仍保持白底。

### 5.5 商城与交易

- 商城使用单页“货架目录”，同时展示全部 8 种消耗品和 2 种永久升级，并在每项中直接显示可复制购买或升级命令。
- 交易、赠送和售卖使用“粉色票据”，重点显示双方、物品、价格、交易号、状态和有效期。
- 我的交易以账簿行展示待处理、已完成、已拒绝、已取消和已过期状态，不嵌套多层卡片。
- 不在交易图中显示双方平台账号原始 ID，只显示群昵称和必要的短标识。

### 5.6 排行榜

- 前三名使用独立但克制的名次色，四至十名使用统一紧凑账簿行，不照搬参考图的深色卡片结构。
- 每人显示当前榜单的核心指标，以及优先使用用户设置、否则自动选择的一个适配展示物。
- 默认综合榜同时显示猪图鉴与美食图鉴进度。
- 同分按达到该分数的时间优先，再按稳定玩家 ID 排序，保证重渲染顺序稳定。
- 动态素材在背包、图鉴和排行榜中使用确定性的中间帧 PNG 预览并标记“动态”；单资产详情继续保留完整动画，原素材不重编码。

建议尺寸 `1200 x 1500`；超出十名必须分页。

## 6. 文本与图片容错

- 显示名、模板名和描述都先做 HTML 转义。
- 显示名最多 24 个可见字符，超出后保留前后信息并省略中间。
- 资产名称最多两行，描述最多四行；超出内容在详情页展示。
- 素材缺失或隐私隐藏时使用模板内的中性 CSS 占位组件；缺失文件明确显示“文件暂缺”，授权撤回明确显示“授权已撤回”。占位组件不是可抽取素材，维护任务会汇总记录缺失数量。
- 渲染图必须在 `320px` 宽群聊缩略图中仍能识别标题、品质和核心数字。
- 图片生成后检查宽高、文件大小、透明通道和非空像素，再调用发送接口。

## 7. 素材交付标准

第二轮 2B 素材建议以压缩包或独立目录提供，不直接混入运行数据。每个猪模板至少包含：

| 字段 | 要求 |
| --- | --- |
| `template_id` | 小写英文、数字、连字符，发布后稳定 |
| `display_name` | 简体中文展示名 |
| `rarity` | `1..6` |
| `description` | 预先审核的静态描述，运行时不调用 LLM |
| `image` | 相对素材路径 |
| `scope` | `common` 或指定群范围 |
| `length_min/max` | 合理体型范围 |
| `weight_min/max` | 合理重量范围 |
| `fat_profile` | `lean`、`balanced`、`fatty` 或参数化分布 |
| `recipe_tags` | 食谱倾向标签 |
| `source` | 原创、授权来源或许可说明 |
| `consent_status` | 6 星群友素材必须填写 |
| `collection_*` | 联动系列、槽位、总量、角色、乐队及官方资料地址 |
| `effect_id/effect_params` | 美食可选效果 ID 与经过校验的一次性参数 |

推荐图片规格：

- 优先 PNG 或 WebP；兼容 JPEG、GIF 和动画 WebP，实际格式按文件内容识别，不依赖扩展名。
- 新增素材建议最短边不低于 1024px；首批用户素材按不低于 200px 的兼容阈值接入。
- 优先透明背景；若保留背景，必须标注裁切方式 `contain` 或 `cover`。
- 主体四周保留至少 8% 安全区。
- 不把名称、星级和数值烘焙进素材，文字由渲染模板统一生成。
- 不提交来源不明、授权不清或包含隐私信息的素材。
- 动画素材必须保留原始帧序列、有效帧时长和循环设置；入库不得重新编码原件。

## 8. 素材目录规划

2B 清单定义与运行素材采用以下边界：

```text
catalogs/formal/
  pig-and-food-definitions.json  # 可审计元数据，进入 Git
asset_library/
  README.md                      # 素材位置和维护说明，进入 Git
  current/                       # 本机当前导入包，Git 忽略
ctx.paths.data_dir/
  assets/catalogs/<catalog-hash> # 原子发布后的运行素材
```

2A 的隐私/缺图占位位于 HTML/CSS 模板，不出现在 `assets.json`、猪模板表或美食模板表中。

6 星群素材不默认提交到公共 Git 历史。它们通过管理面板导入 `ctx.paths.data_dir` 下的范围目录，并用数据库映射到 `scope_id`。

## 9. 素材验收

导入工具必须检查：

1. 清单字段完整且模板 ID 唯一。
2. 品质、属性范围和作用域合法。
3. 文件存在、可解码、尺寸足够且无越界相对路径。
4. 1 至 5 星不得声明群专属，6 星不得默认声明全局公共。
5. 6 星具有授权和撤回信息。
6. 动画逐帧可解码，帧数、总时长、循环和输出大小处于配置限制内。
7. 所有素材在正式卡片与群聊缩略尺寸完成视觉抽检，动画同时检查代表帧。
8. 不将参考图中的水母素材、布局截图或其衍生裁切当作项目资产。

当前正式目录已接入 102 项素材，其中 83 只猪、19 道美食、9 项动画和 4 项群专属六星素材。新增“猪寿司拼盘”“一猪六吃”“猪咪虾寿司”“猪猪玉子烧”均保留用户原图字节并通过完整卡片验收。联动系列的分母固定为角色团体总人数 `5`，未交付槽位仍保留为未收集状态。
