# 视觉与素材规范

## 2.0 美术层（2026-08-29）

2.0隔离开发线的新增规范以[第三阶段实施记录](32-art-and-balance-integration.md)及
[正式外观包说明](design/phase3/cosmetics-implementation.md)为准；以下原1.x规范继续约束原始猪菜素材、
信息优先级、白底淡粉及网络隔离，不把2.0开发成果视作已上线。

- 称号是精美横向收藏牌；整卡边框、徽章、周榜名次牌各有独立资产身份。奖励数据仍由业务层判断归属。
- 已制作83项真实奖励外观。普通/高级主题插画由7张原创母版构成，中文与名次用代码精确排版，
  每项有独立图形装饰。母版为白底RGB；成品外轮廓及九切片使用透明层，不能把母版宣称为透明抠图。
- 装饰不替代数据：图面不出现新奖励、虚构概率、隐藏条件或玩家内部ID。未解锁隐藏奖励不读美术文件。
- 抓猪和做菜素材槽保持 `x38/y164/480×480`；文字区改自然增高。最终概率先于长效果，
  多次剩余、未参与来源和实际归属分别展示；原始动图仍保留逐帧合成。
- 多资产清单沿用背包的有界中间帧缩略预览并标明动图；不把静态清单说成完整动图播放。
- 纪念牌允许独立轮廓及细金边；功能回执使用12–18px圆角和细线/浅色分区，普通数据仍清晰可读。
  不为每项字段额外套复杂背景。UI图标采用受控原创SVG白名单，不依赖Emoji字库。
- 主动佩戴后显示真实称号/徽章及边框；首期活动的1/2/3/10牌只用于第1期，未来新期不得套用旧牌。
- dev12补齐真实三格徽章：默认1槽、里程碑权益3槽，空位和槽号可见；抓猪、做菜、档案、背包、
  榜单和三系统共用同一投影。右侧详情宽度计入根边框，不能靠隐藏溢出裁掉文字或移动动画槽。
- 运行使用有界WebP预览、透明九切片和缓存；详细外观使用精确文字PNG。损坏/缺失装饰安全回退，
  不消耗资产或重新抽奖。帮助、权限拒绝和报错继续保留可复制文字。

完整场景与检查说明见[功能卡](design/phase3/feature-rendering.md)和[指令出口审查](design/phase3/command-render-audit.md)。
全素材/功能卡实渲、320px联系表、长效果与动画保真及生产副本/恢复结论见
[全量验收报告](34-v2-final-acceptance.md)。真实QQ投递仍未执行；完整动画可能超过8–11MB，
本地编码通过不等于官方通道上传成功，不为通过验收擅自降帧或重绘原素材。

## 1. 设计立场

参考图只用于确认信息需求：

- 单次获得需要突出素材、品质、名称、属性、价值和新纪录。
- 背包需要同时表达筛选、数量、关键属性和分页。
- 图鉴需要区分已收集、未收集和各品质进度。
- 排行榜需要让名次、展示物和统计在群聊缩略图中仍可辨认。

新插件不复刻参考图的水母主题、深蓝背景、面板边框、卡片比例、装饰符号和具体排版。新视觉采用独立的“白色收藏册与淡粉称重票据”语言，整体轻盈、明亮、有一点群聊整活感，但不能牺牲可读性。

## 2. 视觉关键词

- 白色收藏册
- 淡粉票据
- 称重印章
- 清爽图鉴
- 轻松但不幼稚
- 稀有品质有辨识度，普通信息保持安静

避免：

- 大面积深色背景
- 单一粉色覆盖所有信息层
- 多层卡片嵌套
- 过度圆角、发光、玻璃拟态、渐变球和无意义装饰
- 把文字压在复杂素材上
- 为追求可爱而降低对比度

## 4. 排版与组件

- 中文字体优先使用可随插件合法分发的开源 CJK 字体；系统字体只作后备。
- 标题、名称、正文、数据使用明确的四级字号，不用随视口宽度连续缩放字体。
- 字距固定为 `0`。
- 圆角不超过 8px；只有图片裁切、单个物品单元和真正的回执区域使用边框。
- 页面分区优先使用留白、细线和浅粉色横带，不把整页切成层层悬浮卡片。
- 数字使用等宽数字特性，体型、重量、价值和排行分数右对齐。
- 状态图标使用 MaiBot 或现有图标库中的标准图标；不手绘替代常见图标。

## 5. 渲染模板

### 5.1 单次抓取

采用竖向“称重证书”：

1. 顶部为品质、猪名、获得者和时间。
2. 中部为完整素材，保持主体可见，不做过暗或过度裁切。
3. 下部为称重票据，横向展示实际体型、实际重量、直观体态和价值，不展示内部百分位。
4. 底部显示猪币、经验、图鉴状态和纪录结果。
5. 新纪录使用独立印章位，不通过全页发光表达。
6. 首次收集显示独立 `NEW` 标记；迷你、巨型或极端个体显示一条体型评价。
7. 达到绝对体型或重量门槛时显示“全群纪录”和“巨物目击”标记。
8. 成功抓取增加独占的“本次最终概率”整行，并在下一行列出等级、饲料、道具与菜品来源；
   六星菜独占时明确写出其他来源未参与。
9. 群级六星菜实际参与本次结算时，以“发动群友：QQ 昵称”署名；禁止在结果图中渲染
   数字 QQ 号、QQ 官方 OpenID 或内部玩家键。

建议宽度 `1200`，普通详情高度约 `860`；成功抓取含概率行时自动扩展到约 `950`，
长描述与概率行同时存在时继续扩展，禁止用固定高度裁掉概率或覆盖页脚。素材安全区至少
`640 x 430`。

### 5.2 猪猪与美食背包

采用“收藏册展开页”：

- 顶部单行显示用户、余额、等级、筛选和页码。
- 主体固定四列，单元尺寸稳定，长名称换行而不挤压图片。
- 每个单元只显示素材、品质、名称、短编号和一种当前排序指标。
- 收藏实例在短编号行追加克制且清晰的 `♥ 已收藏` 文字标记；不能只靠颜色表达保护状态。
- 页面底部显示总数、总价值和翻页提示。
- 详情信息通过详情命令查看，不在一个小单元里堆满所有数据。

建议宽度 `1200`，每页最多 12 项，高度由行数限定在 `900..1700`。

### 5.3 图鉴

采用“索引册”而不是背包复制：

- 每个品质使用整行标题带和收集进度。
- 已收集条目显示素材和最佳纪录；未收集条目显示统一剪影与编号。
- 当前群已授权但未发现的 6 星条目只显示保密占位，不显示姓名、轮廓或描述。
- 未授权群不显示其他群的专属条目，也不把它们计入图鉴总数。
- 图鉴不分页；当前筛选的全部条目按一至六星顺序输出到一张完整长图。
- 使用五列紧凑稳定单元和独立品质标题，在完整展示的同时控制高度与发送体积。
- 完整正式库必须以每个授权群可见 92 只猪、24 道美食的规模检查裁切、坏图、非空像素和 PNG 大小。

### 5.3a 批量做菜

复用背包“收藏册展开页”的多菜合一布局，不逐菜出图：

- 顶部展示消耗原料猪数量与本次产出总份数，品质胶囊显示筛选范围。
- 一条三格统计条展示本次猪币、经验与新增图鉴数。
- 主体四列稳定单元展示每份成品素材、品质、名称、短编号、份量与官方价值。
- 产出严格按品质从高到低排列，同品质按产出先后排序。
- 底部固定提示“做菜冷却 10 秒；每种联动猪保留价值最高的一只，六星定制猪不参与批量处理”。

### 5.4 美食结果

采用“厨房出餐单”：

- 原料猪以小型来源章展示。
- 成品素材是视觉主体。
- 品质、菜名、偏肥瘦类型、份量、价值和效果明确分区。
- 品质名称与星级必须是第一视觉层级，高于实例编号和技术媒体信息。
- 展示厨具和本次消耗品加成，并用一条紧凑六档概率与一条来源说明展示最终结算；
  不同时重复显示“最终品质概率”和“本次最终概率”。
- 做菜成功图把最终概率与来源放在回执中的独立审计区，位置必须先于成品效果、本次菜品加成
  和互斥未叠加说明；概率区及页脚随内容自然向下延展，禁止长效果把概率挤出画布。
- 6 星结果可使用更丰富的分段边线，仍保持白底。

### 5.5 档案、商城与交易

- 档案在等级进度下方显示当前等级单独带来的抓猪与普通做菜概率，保持一行主值、一行封顶说明；
  `Lv.21+` 另设猪币里程碑区，显示当前档、该档一次性猪币、累计猪币、领取状态和下一档奖励，并明确概率收益仍在 `Lv.21` 封顶。
- 主商城使用单页“货架目录”，以自适应概率带展示猪饲料和厨具 `Lv.0-10`，再展示
  幸运/超级幸运猪哨、星辉探猪镜、主厨/超级主厨香料的前后概率，最后列出全部 16 种
  消耗品和 2 种永久升级；当前等级使用淡粉描边，不依赖颜色作为唯一信息。
- 派遣、巡演、对战各有独立器具商城图，不混入主商城“全部”；每项显示玩法图标、效果、
  单价和可复制购买命令，隐藏与该分区无关的主商城概率带。
- 商城每项直接显示可复制购买或升级命令；六星猪 90/10 基础、超级香料提升到 20% 及
  六星菜独占规则与概率带同屏说明。
- 交易、赠送和售卖使用“粉色票据”，重点显示双方、物品、价格、交易号、状态和有效期。
- 我的交易以账簿行展示待处理、已完成、已拒绝、已取消和已过期状态，不嵌套多层卡片。
- 不在交易图中显示双方平台账号原始 ID，只显示群昵称和必要的短标识。

### 5.6 排行榜

- 前三名使用独立但克制的名次色，四至十名使用统一紧凑账簿行，不照搬参考图的深色卡片结构。
- 每人显示当前榜单的核心指标，以及优先使用用户设置、否则自动选择的一个适配展示物。
- 默认综合榜同时显示猪图鉴与美食图鉴进度。
- 同分按达到该分数的时间优先，再按稳定玩家 ID 排序，保证重渲染顺序稳定。
- 背包、图鉴和排行榜统一使用最长边不超过 256px、质量 82 的静态 WebP 紧凑预览；动态
  素材取确定性的中间帧。单资产静态卡使用最长边不超过 768px、质量 90 的 WebP 衍生预览，
  单资产动画继续完整逐帧合成；所有原素材字节保持不变。

建议尺寸 `1200 x 1500`；超出十名必须分页。

### 5.7 今日巨物

- 使用一张白粉长图同时展示“最大体型榜”和“最重体重榜”，顶部显示北京时间日期、
  今日抓猪总数和参榜人数。
- 两榜各最多显示排行配置规定的人数，每位玩家每榜只出现一次；前三名沿用克制的金银铜名次色。
- 每行显示玩家昵称、猪名、品质、短编号、抓到时间、体型和重量；主指标放大，另一项作为副指标。
- 紧凑素材继续使用最长边不超过 256px 的静态 WebP 预览，动态素材取确定性中间帧。
- 空榜也生成完整图片并明确显示“今天还没有抓到猪猪”。

### 5.8 六星盛宴全群通告

- 使用独立的 `group_event.html`，顶部必须有“全群通告”圆章、事件标题、发动群友 QQ 昵称、
  生效群聊和时间；不渲染数字 QQ、QQ 官方 OpenID 或内部玩家键。
- 糖醋排骨资格、神龙化猪七星云海锅结算、糖醋排骨正式重置分别使用玫粉、紫金、橙金色调，
  但保持白底淡粉体系、8px 以内圆角和清晰的 320px 群聊缩略图可读性。
- 资格与云海锅通告展示对应菜品素材；重置通告使用稳定 CSS 六星占位，不虚构新的素材。
- 主数字只显示一个事件核心，下面三列展示猪币、专属次数与概率边界；资格通告必须突出
  `1 次 /重置额度` 和“尚未重置”，正式通告必须突出“每人 10 次”。
- 三张长图目标为 `1128 × 1080` 左右；长昵称、长群名和完整规则文本必须零裁切、零越界、零坏图。

## 6. 文本与图片容错

- 显示名、模板名和描述都先做 HTML 转义。
- 显示名最多 24 个可见字符，超出后保留前后信息并省略中间。
- 资产名称最多两行，描述最多四行；超出内容在详情页展示。
- 素材缺失或隐私隐藏时使用模板内的中性 CSS 占位组件；缺失文件明确显示“文件暂缺”，授权撤回明确显示“授权已撤回”。占位组件不是可抽取素材，维护任务会汇总记录缺失数量。
- 渲染图必须在 `320px` 宽群聊缩略图中仍能识别标题、品质和核心数字。
- 图片生成后检查宽高、文件大小、透明通道和非空像素，再调用发送接口。
- 传给 `render.html2png` 的 HTML 在插件侧执行 UTF-8 字节预检，安全上限为 12 MiB；禁止把完整正式素材库的原始大图直接 Base64 内联进一个 RPC 请求。
- 图片生成与发送默认共用 2 个交付名额；等待超过 5 秒时不再启动额外渲染，直接使用同一
  回执的完整文字结果。日志分别记录排队、渲染、发送耗时和最终图片字节数。
- 素材解码、缩放和 WebP 编码默认最多并发 2 个；衍生预览使用 8 MiB 进程内 LRU 和
  `data_dir/cache/render-previews-v1/` 下最长 64 MiB 的磁盘缓存，同一缓存键并发请求只生成一次。
- 动画卡片默认只允许 1 个合成任务；合成后的待编码帧立即量化为调色板图，并在建立整卡
  帧列表前按画布与帧数检查 256 MiB 工作内存预算，超限时在大内存分配前走文字兜底。

## 7. 备用图与显示变体

部分六星定制猪（如保千猪）除主立绘外，还提供一张独立表情包作为 `alternate_image`：

- `AssetManifestEntry` 中通过 `alternate_image` 声明表情包文件，构建和导入时与主图同样进行格式、尺寸与路径校验。
- `pig_templates` 保存 `alternate_image_relpath`，`pig_instances` 保存 `display_variant`（`pig` 或 `sticker`）。
- 默认变体为 `pig`；玩家通过 `/切换 猪保千` 切换后，对应实例在详情、背包和图鉴中渲染表情包。
- 单次抓取成功时，若模板存在 `alternate_image`，会先把表情包作为独立图片发送，再按原有流程渲染并发送猪猪卡片；卡片上显示“输入 `/切换 猪保千` 可在猪猪立绘与表情包之间切换”。
- 表情包和主图均不得依赖外部网络，必须随素材包进入运行时目录。

## 7. 素材交付标准

第二轮 2B 素材建议以压缩包或独立目录提供，不直接混入运行数据。每个猪模板至少包含：

| 字段 | 要求 |
| --- | --- |
| `template_id` | 小写英文、数字、连字符，发布后稳定 |
| `display_name` | 简体中文展示名 |
| `rarity` | `1..6` |
| `description` | 预先审核的静态描述，运行时不调用 LLM |
| `image` | 相对素材路径 |
| `alternate_image` | 可选备用立绘/表情包路径；必须与主图接受相同的安全、格式和哈希校验 |
| `scope` | `common` 或指定群范围 |
| `length_min/max` | 合理体型范围 |
| `weight_min/max` | 合理重量范围 |
| `fat_profile` | `lean`、`balanced`、`fatty` 或参数化分布 |
| `recipe_tags` | 食谱倾向标签 |
| `source` | 原创、授权来源或许可说明 |
| `consent_status` | 6 星群友素材必须填写 |
| `collection_*` | 联动系列、槽位、总量、角色、乐队及官方资料地址 |
| `effect_id/effect_params` | 美食可选效果 ID 与经过校验的一次性参数 |

推荐图片规格：

- 优先 PNG 或 WebP；兼容 JPEG、GIF 和动画 WebP，实际格式按文件内容识别，不依赖扩展名。
- 新增素材建议最短边不低于 1024px；首批用户素材按不低于 200px 的兼容阈值接入。
- 优先透明背景；若保留背景，必须标注裁切方式 `contain` 或 `cover`。
- 主体四周保留至少 8% 安全区。
- 不把名称、星级和数值烘焙进素材，文字由渲染模板统一生成。
- 不提交来源不明、授权不清或包含隐私信息的素材。
- 动画素材必须保留原始帧序列、有效帧时长和循环设置；入库不得重新编码原件。
