## 1. 已实现范围与快速上手

乐队档案、三套阵容、九团角色招牌、曲库与编排、逐站/一键、养成/器材/器具、粉丝/档期、
联演、票根/照片/主题收藏、游记、独立保护和主要图片形成闭环。未新增战斗入口或修改生产 1.29.1。

下面是隔离验收环境中的示例；需已经拥有对应猪，也可以换成自己拥有、职能完整的音乐角色猪。

```text
/组建乐队 今天也要上台
/乐队编队 1 星星猪、巴巴猪、LAYER猪
/猪猪巡演 确认
/我的猪猪乐队
/猪猪巡演 排练
/巡演一键
/猪猪巡演 确认
/巡演游记
```

也可以 `/猪猪巡演 出发`，确认后用 `/巡演继续` 逐站演，或者随时 `/巡演一键` 完成剩余站点。
出发确认时才扣一张档期；出发本身不强制演完第一站。首次编队与出发是两次独立确认。

| 入口 | 主要操作 |
| --- | --- |
| `/组建乐队 名字` | 首创或恢复自己的乐队档案；解散恢复不重置资源 |
| `/乐队编队 1 猪名、猪名、猪名` | 保存 1–3 号阵容；可写 `清空`，变更需确认 |
| `/我的猪猪乐队` | 当前阵容、站位、档期、粉丝、器材；支持 `阵容 2`、`切换 2` |
| `/我的猪猪乐队 角色 1`、`成员 1` | 角色目录/招牌与自己拥有的可培养实例，支持页码 |
| `/我的猪猪乐队 改名 名字` | 另有 `简介 内容`、`主题色 粉`、`队徽 星星`、`服装 主题名` |
| `/我的猪猪乐队 队长 1`、`中心 1` | 以当前阵容位置、名称或精确编号选择；中心须有主旋律职能 |
| `/乐队练习 猪名` | 今日付费练习预览；确认才扣材料和猪币 |
| `/我的猪猪乐队 风格 猪名 技术` | Lv.3 开启；亲近/技术/叙事互斥，改选需成本与确认 |
| `/我的猪猪乐队 器材`、`器材 升级` | 看五级成本、升级预览；器材只影响巡演评分 |
| `/我的猪猪乐队 器具`、`制作 备用线缆 2` | 看配方/库存，支持一次制作 1–99 件 |
| `/猪猪巡演 场地`、`主题`、`曲库 1`、`合奏` | 查看版本化目录、开放条件和原创故事 |
| `/猪猪巡演 主题 星星落进练习室` | 给未演出站点载入主题及三首推荐曲目 |
| `/猪猪巡演 路线 街头舞台、校园祭、Livehouse` | 三个场地须已解锁；支持同场地三站 |
| `/猪猪巡演 编排 1 1、2、3` | 第 1 站的三首不同歌曲，可用曲目编号或完整名字 |
| `/猪猪巡演 高光 1 1、2` | 第 1 站两位角色；也可 `自动` |
| `/猪猪巡演 合奏 1 自由合奏` | 指定组合、`自动` 或 `无`；必须满足实际成员条件 |
| `/猪猪巡演 器具 1 备用线缆` | 第 1 站最多一种器具，演出才消费；`无` 取消 |
| `/猪猪巡演 排练` | 免费确定性预估；不花档期、不获得任何进度 |
| `/猪猪巡演 出发`、`/巡演继续`、`/巡演一键` | 三站状态机与一次性结算，不能重抽已演完站点 |
| `/猪猪巡演 结束` | 确认提前落幕，不退档期；保留已完成站的成长和照片 |
| `/巡演游记 1`、`/巡演游记 T开头编号` | 历史分页、三站详情；`收藏 1` 查巡演收藏册 |
| `/巡演联演 @群友` | 同群受邀者五分钟内 `/巡演联演 接受` 或 `拒绝`，邀请者可 `取消` |
| `/我的猪猪乐队 客串 绿茶猪` | 已授权拥有的特邀客串；不占器乐位、不加评分/训练，可 `取消` |
| `/我的猪猪乐队 解除保护 猪名` | 预览后确认，从三套阵容/客串移除并允许之后处置，成长不删除 |
| `/我的猪猪乐队 解散` | 确认归档，保留档期、粉丝、成长及保护，不刷首创奖励 |

所有两分钟确认统一用 `/猪猪巡演 确认`、`/猪猪巡演 取消`，不接管吃菜的 `/是` 或 `/否`。
同名选择优先最低价值的可用非收藏实例，图中先展示具体编号。收藏猪可用精确 `猪名#编号` 点名后确认，
原收藏标记不变。纯帮助保持可复制文字，其他主要结果优先图片。

## 2. 开发取值与补充契约

- 一名玩家一个持久乐队档案，保存三套阵容；3–5 个实例、至少三个不同角色，覆盖主旋律、节奏、伴奏。
  同角色形态可趣味同台，但按阵容首个实例代表该角色计分，不重复提供职能、高光、经验或默契。
- 初创两张档期，此后北京时间跨日补一张，最多七张；满仓仍推进补给日期，不补存溢出的历史档期。
  改名、解散重建不重置粉丝、档期、曲目或本人培养历史。无随机掉级，不消耗猪。
- 五场地开放粉丝为 0/200/1000/3000/8000；一张档期跑三站，标准场租已包含。
- 每站评分上限为演出35、默契25、编排25、舞台10、设备5。职能覆盖15、中心位与编制5、平均训练等级15；
  默契最多12（本人成员合作30站）、歌曲熟练最多13（每曲10次）；观众匹配12、递进曲序9、首尾动机呼应4。
  主题与两位高光、一个合奏共同组成舞台项；原团和混团同上限。现场变化最多±3分。
- 初始曲库27首原创歌曲卡、九个主题，所有团都能演任何主题，不分发音频、官方谱面或新增官方图包。
- 每站自然训练20经验；0→10级累计2200经验。本人贡献与转入训练分开，满级仍记录正式演出经验。
  每实例每天一次付费练习：5舞台组件+3补给+50猪币，50经验；已满级不再扣费。
- 训练3级可选亲近/技术/叙事风格，同层互斥；首次免费，改选需3组件+2补给+20猪币，预览确认。
- 舞台器材0→5级，每级贡献1设备分。各级额外成本依次为
  `组件/零件/纤维/猪币 = 20/10/5/100、40/20/10/200、80/30/20/400、140/40/30/800、220/60/40/1400`。
- 每站至多一件器具：备用线缆（2零件+1补给）、提示卡（2纤维+1补给）、留声机（2组件+1补给）、
  礼花（2补给+1纤维）。分别用于设备失误保护、补足最多2编排分、额外成员留影、纯视觉谢幕。
- C/B/A/S/SS依次为低于50、50、65、80、92分；整趟用三站平均最终分评级，一次给
  40/60/80/100/120粉丝及200/260/340/420/500猪币，不按歌曲重复发奖。
  票根、主题海报、高光和舞台收藏有独立收藏册，不冒充第四轮成就奖券。
- 免费排练不生成随机种子、不发任何进度。出发确认固定整趟随机种子；继续与一键共用逐站评分和结算。
  站间释放占用，下一站重新检查阵容、所有权和材料，换人差异明示，不能重抽已完成站。
- 联演邀请有效五分钟，双方各自一个待处理邀请；接受时重新核对邀请快照与两个玩家资格，
  原子消耗双方各一张档期并完成各自三站，生成共同海报，各得一份正常奖励，无额外经济倍数。
- 常用阵容/培养默认另加乐队保护，不篡改收藏开关；销毁、转让前须确认解除保护并从三个阵容移除。
  训练和历史不删除。正式演出/付费练习使用第一轮统一占用，不能与派遣、交易、未来战斗重叠。

九主题装扮是本轮巡演收藏，不是第四轮成就奖励。`服装` 表现为巡演卡面的主题舞台装饰和标签，
队徽使用九种原创 UI 符号，不表示已重绘一套角色衣服或复制了官方团标。`服装 默认` 可恢复。

## 3. 角色、评分与可扩展性

- `tour_characters.json` 保存九团 47 主体形态；规范身份 45 个。美咲/米歇尔、黄瓜/墨提斯同身份，
  初华帽子是既有立绘切换，不另造新模板。八个明确的群定制模板别名映射到对应彩/祥子身份。
- 角色身份、乐器、职能、原创招牌与触发条件独立定义；27 歌曲、九主题、五场地、16 合奏、四器具
  与评分器分离。不能凭名称猜角色，也不能因同名多形态多拿经验与高光。
- 每站保存真实评分原值、每项修正及其实际应用量、五项封顶后值、现场波动和最终等级。
  个人高光最多两个、合奏最多一个，失误保护、下站准备、额外留影、场景收藏都有具名处理器。
- 没有原团人数或稀有度乘数。三人混团、LAYER 加双鼓无键盘、五人组合和九个主题均用真实公式
  验证 S/SS 可达，不在测试中直接设置等级结果。模板重量、售价与抓猪效果不参与演出。
- 新角色/曲库/组合优先追加定义；需要新效果时增加有测试的处理器，不把中文描述解析成脚本。
  `TOUR_VERSION=1` 随巡演/阶段/活动事实保存；不兼容版本明确拒绝继续，后续须做迁移或保留旧处理器，

## 4. 数据、事务和旧玩法保护

| 层 | 代码入口与职责 |
| --- | --- |
| 定义/纯规则 | `domain/tour_catalog.py`、`domain/data/tour_characters.json`、`domain/tour.py` |
| 命令 | `commands/tour.py` 严格解析；`plugin.py` 四个显式组件及别名，无普通消息监听 |
| 迁移 | `infrastructure/migrations/v0038_tours.py`，15 张新表及关键索引、保护/不可变触发器 |
| 仓储 | `infrastructure/repositories/tour.py`，档期、训练、单站、完成、收藏和活动事实 |
| 应用 | `services/tour.py` 回执/事务；`tour_setup.py` 确认/养成/设置；`tour_joint.py` 双向联演 |
| 投影 | `services/tour_queries.py`、`domain/tour_views.py`，图片和完整降级文字同源 |
| 图片 | `rendering/templates/tour.html`、`render_tour`；使用既有缩略图/渲染/发送限流 |

Schema 38 表：`tour_profiles`、`tour_ticket_ledger`、`tour_rosters`、`tour_proficiency`、
`tour_contributions`、`tour_song_progress`、`tour_protections`、`tour_practice_days`、`tour_runs`、
`tour_stages`、`tour_tools`、`tour_collections`、`tour_pending`、`tour_joint_invites`、`tour_joint_reservations`。
旧表原行、正式 173 猪/79 菜、猪币和现有材料不改写。当前版启动检查同时要求新表、关键索引和保护约束齐全。

确认、付费资源、站点、成长、收藏、奖励、回执在同一个写事务中提交；渲染在提交后。
一键和联演不跳过逐站逻辑。联演第二方出错会整体回滚，不能只扣第一方档期。两条连接收到同一确认消息
只会产生一次结算；不同消息再次接受已完成邀请仅返回旧结果。备份恢复和继续不会更换种子。

乐队保护与“正在活动”是两回事：静态阵容保护不锁住派遣；实际演出才短时占用，结束即释放。
保护先于名称选择、批量保留和 `LIMIT` 排除；精确编号、管理员处置和底层更新/删除也受保护。
解除保护须显式确认并从三个阵容移除，收藏仍保留；转出时保留训练，转入训练猪自动为新主人重新保护。
本人付费/自然经验与默契不会跟随交易冒充新主人培养；每实例的当日练习限制也不能靠转手重置。

所有玩家与记录仍严格按 `platform + group_id` 隔离。四个群作用域共用规则，不合并钱包、成员或档期。
私人/群专属素材需要当前授权；授权撤销后阻止新演出，历史和重放图片重新遮罩，仍允许解除保护。
展示使用昵称，不在公开投影中输出官方 OpenID、内部玩家键或随机种子。联演的前导 @机器人不充当目标群友。

## 5. 第四轮事实接线与资源控制

`activity_facts` 使用 `source_type=tour`，稳定键由玩家、来源和子事件构成。已持久化：

- `started`、`stage-1/2/3`、`completed`、`abandoned`：实际阵容实例/规范身份/形态/原团、主题、场地、
  队长/中心、逐站评分、高光及触发情况、组合、器材、消耗器具、发生时间和完成状态。
- 每实例自然/付费训练：前后总经验、本人有效经验、来源类型；满级仍保留自然经验事实。
- 器材升级与制作：支付者、材料明细、猪币、前后级、实际自然舞台组件历史；单站保存真实装用器材等级。
- 联演 `joint-completed`：双方稳定身份、共同联演 ID、各自巡演 ID、各花一张档期、双方三站完成。
  两个人都得到事实，不只记命令发送者。

这些事实供 T 类与 X 类新增成就后续消费；当前不会注册 48 项新成就、发尚不可用的新券或扩大旧 49 项毕业。
目录仍为旧 82 项，巡演回执不记入抓猪数量或首期抓猪价值榜；真实奖励猪币保持既有累计收入口径。
离线开发事实不能导入生产发奖。不可变账本/事实不是缓存，不能为省空间未经归档校验直接清理。

没有逐成员定时器、长期网络会话或后台常驻演出任务。档期按日期惰性补给；单次最多三站、联演最多六站，
列表分页，图片只携带已有有界预览，不把原图/base64 写进数据库。性能与存储规模仍需在最终生产克隆门禁验证。
