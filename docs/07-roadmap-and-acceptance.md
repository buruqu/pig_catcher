# 开发路线、验收与待确认项

## 1. 分轮计划

### 第一轮：需求与工程准备

状态：已完成设计产物，待本轮最终审计。

- 完整需求解析
- 领域、数据、命令、概率、经济和视觉设计
- 第二轮素材交付规范
- 独立 Git 仓库
- Codex 专用 Skill
- 不创建插件运行框架

### 第二轮：完整框架与素材管线

输入：用户提供的第一批正式素材和对待确认项的结论。

第二轮拆成两个可独立验收的小阶段。

#### 2A：无正式素材框架期

状态：已完成并通过本地工程验收。

- 标准 `_manifest.json`、`plugin.py`、配置模型和包结构
- SQLite 初始化、迁移器、仓储接口和事务管理
- 命令注册骨架，但不使用普通消息监听或 LLM
- 素材清单协议、合成测试素材校验和 6 星群素材隔离
- 白底淡粉渲染主题、字体、占位图和基础模板
- 随机源、时钟、消息 ID 和发送器的可测试接口
- pytest、编译、Manifest、加载和卸载验证

占位图只用于缺图和隐私保护，不进入可抽取模板池。未闭环的玩法命令不得返回假成功。

#### 2B：正式素材接入期

状态：已完成并通过本地工程、全素材视觉和运行中宿主加载验收。

已完成：

- 1 至 5 星公共素材清单、授权、属性范围和真实加载
- 6 星素材的所属群、授权、撤回与隔离实测
- 83 只猪、15 道美食及其静态整活描述
- 9 项 GIF/动画 WebP 的原动画保真合成
- 5 只 BanG Dream 联动猪与按乐队固定 `X/5` 的收集元数据
- 98 个模板在正式素材卡片和群聊缩略尺寸中的视觉验收
- 生产素材校验值、公共 Git 收录范围和真实素材 UAT

第二轮验收不以“文件存在”为准，而以空素材、合法素材、非法素材、空数据库、重启和配置更新都能通过测试为准。独立字体、图标和品牌元素未随首批素材交付，不阻塞素材目录本身的 2B 验收。

### 第三轮：抓猪与收藏

状态：已完成代码、自动化、Chromium、运行中宿主加载和正式素材隔离命令 UAT。

- 抓猪概率、属性、价值、奖励和经验
- 每日次数、冷却、道具装备
- 猪背包、详情、图鉴和群纪录
- 单次抓取、背包和图鉴图片
- 幂等与重启保护

### 第四轮：做菜与经济

- 做菜矩阵、肥瘦食谱、厨具和 4 种做菜道具
- 美食背包、图鉴、详情、吃菜效果接口
- 商城、升级、官方售卖和账本
- 做菜、商城和回执图片

### 第五轮：社交与排行

- 赠送
- 两阶段交易、过期解锁和并发保护
- 展示物设置
- 七类排行榜和排行榜图片
- 中文管理面板的完整访问控制和维护入口

### 第六轮：全量实机验收

- MaiBot 真实加载、重载和停止
- QQ 群内完整命令回归
- 多用户、多群、重复消息和并发交易
- 图片发送失败、数据库繁忙、素材缺失和重启恢复
- 账本对账、备份和恢复演练

## 2. 全量验收标准

### 2.1 功能

- 六档抓猪概率和所有修正与设计一致。
- 每只猪具有有效且相关的体型、重量、肥瘦率和价值。
- 最大体型与最大重量分别正确更新群纪录。
- 1 至 5 星公共素材可用，6 星素材严格按群隔离。
- 背包、图鉴、做菜、吃菜、商城、升级、售卖、赠送、交易、展示和排行均完整。
- 6 星猪做菜只产生 5 星或 6 星，频率为 90/10。
- 六阶段等级和经验累计正确。

### 2.2 交互与视觉

- `/抓猪帮助` 是便于复制的纯文字。
- 所有业务查询和成功结果都有白色、淡粉主视觉的独立渲染图。
- 不复刻参考图主题和布局。
- 长名称、缺图、零数据、满页和多页都不重叠、不溢出。
- 图片发送失败时有完整文字兜底，业务不回滚。

### 2.3 数据与安全

- 不监听普通消息，不调用 LLM，不修改 MaiBot 核心。
- 跨群查询、赠送、交易和 6 星素材读取全部被拒绝。
- 重复消息不会重复发奖、扣物、转账或公示。
- 进程重启后幂等保护、报价锁和资产状态仍有效。
- 余额不为负，账本可重算，交易双方和物品在一个事务中完成。
- 未授权或已撤回的群友素材不再用于新抽取。

### 2.4 工程质量

- `pytest` 全通过。
- Python 编译和 Ruff 检查通过。
- Manifest 与配置解析通过。
- 插件加载、卸载、配置更新和重载通过。
- 渲染截图完成桌面尺寸和群聊缩略图检查。
- 数据库从空库初始化、逐级迁移和备份恢复通过。

## 3. 必测场景

1. 首次抓取、重复模板抓取、打破体型纪录、打破重量纪录和两项同时破纪录。
2. 群 A 有 6 星素材、群 B 没有；群 B 永远不能抽到或查看群 A 素材。
3. 同名猪有三只，未给短编号时不得误消耗。
4. 1 星猪与 5 星猪的做菜概率边界。
5. 6 星猪在固定随机源下覆盖 5 星和 6 星结果，永不出现其他结果。
6. 做菜数据库提交成功但图片发送失败，原料只消耗一次且美食仍存在。
7. 同一抓猪、售卖、赠送、接受交易消息重复投递。
8. 两个接收请求同时接受同一报价，最多一个成功。
9. 报价后物品不能售卖或再次报价，过期后自动解锁。
10. 余额恰好足够、不足和并发扣款。
11. 素材路径逃逸、损坏图片、重复模板 ID 和授权撤回。
12. 长昵称、长物品名、空背包、满背包和图鉴多页渲染。

## 4. 第二轮素材交付清单

用户提供素材时，最好同时给出：

- 1 至 5 星猪素材目录
- 每张素材对应的猪名、品质和一句描述
- 体型与重量的大致合理区间；没有时允许第二轮提出建议值
- 偏瘦、均衡或偏肥标签
- 首批美食素材及名称；若暂缺，可先只建立食谱元数据接口
- 哪些素材属于 6 星、对应哪个群、是否获得使用授权
- 联动素材的名称、授权、启用时间和是否限时
- 允许分发的字体、图标或品牌元素

原始素材无需按参考图排版，也不要提前把名称、星级和数字写死在图片上。

## 5. 待确认决策

以下项目已给出默认建议，第二轮开始前由用户确认或调整：

| 项目 | 默认建议 |
| --- | --- |
| 正式插件名称 | 暂用“抓猪插件” |
| 目录与插件 ID | `pig_catcher` / `local.pig-catcher` |
| 数据范围 | 每个平台群独立资产、币、等级、纪录和排行 |
| 做菜是否消耗猪 | 是，成功事务中永久消耗 |
| 赠送是否需要接收 | 不需要，发出后立即原子转移 |
| 交易方式 | 两阶段报价，接收方显式接受 |
| 抓猪频率 | 每群每人每日 30 次，间隔 60 秒 |
| 交易有效期 | 5 分钟 |
| 6 星素材 | 群管理员启用、当事人授权、支持撤回，不自动抓头像 |
| 6 星素材进 Git | 默认不进入公共 Git 历史 |
| 具体美食效果 | 等后续素材与玩法补充 |
| 正式作者、许可证和远程仓库 | 2A 暂用 `buruqu`、MIT 和 `https://github.com/buruqu/pig-catcher`；远程尚未创建或推送，发布前可调整 |
| 接受交易时余额不足 | 暂定保持报价待处理直到拒绝、取消或过期；第五轮实现前确认 |

若用户未另行说明，后续轮次继续按这些默认建议实现。

## 6. 变更控制

- 产品规则变化先更新文档和规则版本，再改代码与测试。
- 概率、价值和奖励变化附带数值模拟，不直接凭感觉上线。
- 素材变化通过清单和校验值管理，不覆盖历史来源信息。
- 每轮结束必须更新验收状态、已知缺口和 Git 提交。
- 未经用户明确要求，不推送远程仓库。
