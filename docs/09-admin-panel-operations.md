# 抓猪运营控制面板手册

## 1. 入口与安全边界

在 MaiBot 首页打开“抓猪运营管理”，进入抓猪插件配置。面板提供三类一次性操作：

1. 精准重置一个群的当前抓猪时段；
2. 按成员管理永久赠送/收赠黑名单和永久交易黑名单；
3. 让 Bot 向一个已知群消息流发送一次公告。

同一面板还提供“自动监管”长期策略配置；它不是一次性执行开关，保存后按精确作用域持续生效。

三个执行开关都会在任何数据库修改或消息发送之前自动恢复为关闭。配置重载、插件重启
或发送失败不会自动重复执行。每次重新操作都必须重新打开对应开关并保存。

## 2. 赠送与交易黑名单

在“赠送与交易黑名单管理”分区填写：

- `目标群号`：数据库中已经出现过的精确群号，不接受通配符；
- `平台`：通常留空自动匹配；同一群号存在多个平台时必须明确填写；
- `用户 ID`：一行一个，可填写原始 OpenID/用户 ID、`platform:user_id`，或完整内部身份；
- `赠送与收赠操作`、`交易操作`：两项独立选择“不操作”“加入黑名单”或“解除黑名单”；
- `操作原因`：写入审计，便于以后追溯；
- `执行黑名单变更`：核对无误后打开并保存。

目标成员必须已经在该群使用过插件并存在于插件玩家表。QQ 官方 Bot 应填写成员 OpenID，
不能填写数字 QQ 号或群昵称。任一 ID 无法精确解析时整批拒绝，不会只处理其中一部分。

执行顺序为：只读校验全部身份 → SQLite 在线备份 → 事务内重新校验 → 写入或解除限制 →
加入交易黑名单时取消相关待处理报价并释放资产锁 → 写入 `social-blacklists-updated` 审计。
赠送黑名单同时禁止赠送和收赠猪猪/美食；交易黑名单同时禁止创建和接受猪猪/美食交易。

## 3. 群公告

在“群公告发送”分区填写目标群号、可选平台和公告正文，打开“发送本次公告”并保存。
插件使用该群最近一次由网关写入的 `stream_id` 发送纯文字，因此双 Bot 环境会沿最近活动的
Bot 路由发送，而不是仅凭群号任意选择一个 Bot。

QQ 官方 Bot 的平台限制仍然生效：只有在机器人具备主动消息权限，或目标群最近约五分钟
存在可用的被动回复上下文时，公告才可能成功。面板功能不会绕过腾讯权限。无可用权限、
消息流失效或网关离线时，本次发送会失败并停止，不自动重试。

公告审计事件：

- `announcement-send-claimed`：已经领取本次一次性发送权，包含正文摘要、哈希和消息流；
- `announcement-send-succeeded`：平台发送调用成功；
- `announcement-send-failed`：平台发送调用失败，记录错误摘要。

失败后先检查 MaiBot 和 QQ 官方网关日志、主动消息配置与五分钟上下文，再人工重新打开
开关发送。不要为了补发直接修改数据库审计记录。

## 4. 操作后核验

面板保存后检查抓猪插件日志，确认目标群、处理人数、添加/解除数量、取消报价数量或公告
发送结果与预期一致。黑名单可进一步通过受限账号尝试赠送或创建交易进行人工验收；不要
在生产群使用真实资产做自动化破坏性测试。

数据库审计只读查询示例：

```sql
SELECT action, scope_id, actor_user_id, detail_json, created_at
FROM audit_events
WHERE action IN (
  'social-blacklists-updated',
  'announcement-send-claimed',
  'announcement-send-succeeded',
  'announcement-send-failed'
)
ORDER BY created_at DESC
LIMIT 50;
```

黑名单变更备份默认写入插件数据目录的 `backups/`。备份文件名包含微秒时间，连续操作也
不会覆盖上一份。额度重置的完整规则与命令行备用方案见
[抓猪额度运维手册](08-catch-quota-operations.md)。

当前自动执行范围只有：

- `qq:237716658`
- `qq-official:9EA2810F378FBD7DC3219C56CEAB3520`

`qq:1092931381` 与 `qq-official:5E5854406D0297D6FEAE696A13E3A339` 暂不启用。配置必须填写完整
`platform:group_id`，不能只填末尾群号，也不能用一组范围替代另一平台范围。

群里出现提醒时，不要追加发送内部评分、阈值、路径或证据。管理员可用案件号确认当前状态；
确认误判后使用解除命令并填写简短原因。自动限制均会到期，永久插件/赠送/交易黑名单仍需使用
`/猪管黑名单` 单独人工维护。永久封禁不得通过修改自动限制到期时间来实现。

账号活跃度默认配置如下：

| 配置 | 默认值 | 含义 |
| --- | ---: | --- |
| 群聊活跃回看天数 | 30 | 只统计当前精确聊天流的近期非命令消息 |
| 群聊消息读取上限 | 5,000 | 防止大群查询无界增长 |
| 主账号最少消息/活跃日 | 30 / 7 | 双方均达标且有双向赠送时放宽该互赠 |
| 疑似小号最多消息/活跃日 | 5 / 2 | 还必须同时满足插件账号不满 7 天、玩法动作不超过 10 次 |

插件不分析或保存聊天正文，只把玩家对应的消息计数、活跃日、插件账号年龄和玩法次数写入
内部案件证据；查询能力不可用时层级为“未知”，不会自动把玩家判成主账号或小号。已经生效的
案件和限制不会因为后来达到活跃门槛而自动解除，仍需等待到期或由管理员复核解除。

`qq:237716658 ↔ qq-official:…CEAB3520`。面板中的黑名单、公告和额度目标必须填写
要操作的实际数据范围；平台留空但同一原始群号可匹配多个范围时，面板会拒绝猜测。
四个范围的群专属内容保持同步，不代表玩家 OpenID、黑名单、资产或公告消息流可以跨平台复用。

## 7. 群内插件管理员命令

配置于“访问控制 → 插件管理员”的成员可在目标群发送 `/猪管帮助`。命令固定使用消息中的
`platform + group_id`，不接收另一个群号；QQ 官方接入必须使用成员 OpenID，NapCat 可使用数字 QQ 号。

- `/猪管发币 <@玩家|用户ID> <数量>`、`/猪管扣币 …`：单人调整；管理员扣币可产生负余额。
- `/猪管全员发币 <数量>`、`/猪管全员扣币 …`：对当前群全部已登记玩家原子调整。
- `/猪管发猪|发菜 <@玩家|用户ID> <名称或模板ID> [编号]`：省略时自动生成 8 位字母数字；
  手动编号允许 4 至 16 位英文字母或数字，输入不区分大小写。
- `/猪管删猪|删菜 <@玩家|用户ID> <名称#编号>`：编号大小写均可，保留历史和图鉴，移出有效背包。
- `/猪管黑名单`：查看插件、赠送/收赠、交易三类运行时名单；追加“加入/移除 类别 玩家 [原因]”可修改。
- `/猪管监管 [案件号]`：查看当前群案件概览或指定案件的相关账号与当前临时限制。
- `/猪管监管解除 <案件号> [原因]`：人工关闭案件、释放尚未到期的自动限制，并写监管与通用审计。
- `/猪管重置玩家 <@玩家|用户ID>`：只重置该玩家当前时段次数和冷却。

目标必须已经在当前群留下插件身份；命令不会凭昵称猜测 OpenID，也不会跨群创建玩家。
配置管理员无法加入插件访问黑名单，确保仍能紧急解除错误名单。发放资产不增加抓猪/做菜
统计和奖励；删除资产不做物理删库。所有改变状态的命令均写幂等回执和 `audit_events`，
猪币调整另逐玩家写入 `currency_ledger`。
