# 抓猪运营控制面板手册

## 1. 入口与安全边界

在 MaiBot 首页打开“抓猪运营管理”，进入抓猪插件配置。面板提供三类一次性操作：

1. 精准重置一个群的当前抓猪时段；
2. 按成员管理永久赠送/收赠黑名单和永久交易黑名单；
3. 让 Bot 向一个已知群消息流发送一次公告。

三个执行开关都会在任何数据库修改或消息发送之前自动恢复为关闭。配置重载、插件重启
或发送失败不会自动重复执行。每次重新操作都必须重新打开对应开关并保存。

## 2. 赠送与交易黑名单

在“赠送与交易黑名单管理”分区填写：

- `目标群号`：数据库中已经出现过的精确群号，不接受通配符；
- `平台`：通常留空自动匹配；同一群号存在多个平台时必须明确填写；
- `用户 ID`：一行一个，可填写原始 OpenID/用户 ID、`platform:user_id`，或完整内部身份；
- `赠送与收赠操作`、`交易操作`：两项独立选择“不操作”“加入黑名单”或“解除黑名单”；
- `操作原因`：写入审计，便于以后追溯；
- `执行黑名单变更`：核对无误后打开并保存。

目标成员必须已经在该群使用过插件并存在于插件玩家表。QQ 官方 Bot 应填写成员 OpenID，
不能填写数字 QQ 号或群昵称。任一 ID 无法精确解析时整批拒绝，不会只处理其中一部分。

执行顺序为：只读校验全部身份 → SQLite 在线备份 → 事务内重新校验 → 写入或解除限制 →
加入交易黑名单时取消相关待处理报价并释放资产锁 → 写入 `social-blacklists-updated` 审计。
赠送黑名单同时禁止赠送和收赠猪猪/美食；交易黑名单同时禁止创建和接受猪猪/美食交易。

## 3. 群公告

在“群公告发送”分区填写目标群号、可选平台和公告正文，打开“发送本次公告”并保存。
插件使用该群最近一次由网关写入的 `stream_id` 发送纯文字，因此双 Bot 环境会沿最近活动的
Bot 路由发送，而不是仅凭群号任意选择一个 Bot。

QQ 官方 Bot 的平台限制仍然生效：只有在机器人具备主动消息权限，或目标群最近约五分钟
存在可用的被动回复上下文时，公告才可能成功。面板功能不会绕过腾讯权限。无可用权限、
消息流失效或网关离线时，本次发送会失败并停止，不自动重试。

公告审计事件：

- `announcement-send-claimed`：已经领取本次一次性发送权，包含正文摘要、哈希和消息流；
- `announcement-send-succeeded`：平台发送调用成功；
- `announcement-send-failed`：平台发送调用失败，记录错误摘要。

失败后先检查 MaiBot 和 QQ 官方网关日志、主动消息配置与五分钟上下文，再人工重新打开
开关发送。不要为了补发直接修改数据库审计记录。

## 4. 操作后核验

面板保存后检查抓猪插件日志，确认目标群、处理人数、添加/解除数量、取消报价数量或公告
发送结果与预期一致。黑名单可进一步通过受限账号尝试赠送或创建交易进行人工验收；不要
在生产群使用真实资产做自动化破坏性测试。

数据库审计只读查询示例：

```sql
SELECT action, scope_id, actor_user_id, detail_json, created_at
FROM audit_events
WHERE action IN (
  'social-blacklists-updated',
  'announcement-send-claimed',
  'announcement-send-succeeded',
  'announcement-send-failed'
)
ORDER BY created_at DESC
LIMIT 50;
```

黑名单变更备份默认写入插件数据目录的 `backups/`。备份文件名包含微秒时间，连续操作也
不会覆盖上一份。额度重置的完整规则与命令行备用方案见
[抓猪额度运维手册](08-catch-quota-operations.md)。
