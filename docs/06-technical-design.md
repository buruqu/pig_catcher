# 技术架构设计

## 1. 本机兼容基线

- MaiBot：`1.0.12`
- `maibot-plugin-sdk`：`>=2.7.0,<3.0.0`
- Python：项目兼容目标 `>=3.12`；当前 MaiBot `uv` 运行环境为 `3.14.4`
- 数据库：SQLite，异步访问
- 语言：运行日志、配置面板、命令和用户提示均以简体中文为首要实现

第二轮 2A 已重新读取本机锁文件、SDK 2.7.0 实现和宿主加载器；若后续版本变化，先更新兼容设计再写代码。

2A 已冻结首批版本标识：`schema_version=1`、`asset_manifest_version=1` 和 `ruleset_version=1`。三者独立递增，不能用插件版本代替数据、素材和数值规则版本。

## 2. SDK 映射

| 需求 | MaiBot 机制 |
| --- | --- |
| 用户显式命令 | `@Command` |
| 插件生命周期 | `MaiBotPlugin` 的加载、卸载和配置更新 |
| 中文配置面板 | `PluginConfigBase`、`Field` 和中文 UI 元数据 |
| 发文字与图片 | `self.ctx.send.text`、`self.ctx.send.image` |
| HTML 转 PNG | `self.ctx.render.html2png` |
| 持久化目录 | `self.ctx.paths.data_dir` |
| 临时渲染目录 | `self.ctx.paths.runtime_dir` |
| 日志 | `self.ctx.logger` |

首版不注册普通消息 `@EventHandler`、LLM `@Tool`、模型提供器或网关。联动猪如果未来需要插件间能力，再基于明确用例设计稳定 `@API`，不提前暴露宽泛写接口。

## 4. 配置模型

2A 中文面板分区：

| 分区 | 主要配置 |
| --- | --- |
| 插件设置 | 启用、配置版本、框架阶段 |
| 功能开关 | 当前仅控制纯文字帮助 |
| 访问控制 | 群黑白名单、用户黑白名单、Bot 管理员 |
| 数据存储 | 数据库文件、忙等待、在线备份和保留数 |
| 素材管理 | 清单文件、图片尺寸与大小、暂存清理 |
| 抓猪规则 | 冷却、每日次数、六档权重和缺失六星策略 |
| 做菜规则 | 厨具上限与不可修改的六星 90/10 规则 |
| 猪币经济 | 饲料和厨具永久升级价格 |
| 赠送与交易 | 功能开关、交易价格上限和报价有效期 |
| 图片展示 | 字体、宽度、视口、超时、PNG 上限和文字降级 |
| 运行维护 | 维护任务、间隔和完整性检查 |

关键规则配置需要交叉校验：

- 概率非负且归一化后总和大于零。
- 等级、价格、次数和期限在合理范围。
- 6 星做菜规则不可被配置改成 90/10 之外的值，除非未来需求明确废止该产品规则。
- 黑名单优先于白名单，配置面板明确显示优先级。

## 5. 数据库

- 使用 `aiosqlite` 管理插件自有表，不把自定义模型塞进 MaiBot 核心数据库。
- 数据库默认位于 `ctx.paths.data_dir / "pig_catcher.sqlite3"`，文件名可配置但不能逃逸数据目录。
- 启用 `PRAGMA foreign_keys=ON`、WAL 和合理的 `busy_timeout`。
- 一个数据库连接管理器负责初始化、迁移、事务和关闭。
- 仓储层不提交事务；事务由应用服务统一拥有。
- 迁移文件使用单调版本，测试空库升级和旧版本逐级升级。

### 5.1 并发

- 同一玩家的改变状态命令使用进程内异步锁串行化。
- 交易同时按稳定顺序锁定双方，避免死锁。
- 数据库唯一键和条件更新作为最终防线，不能只相信进程内锁。
- 重启后锁由数据库资产状态恢复，不依赖内存。

### 5.2 幂等

幂等键优先使用平台提供的消息 ID；若适配器缺少消息 ID，使用经过审计的稳定事件键，不用当前时间生成。

`command_receipts` 至少保存：

- 幂等键、命令、玩家、群范围
- 业务结果类型和业务对象 ID
- 文字摘要
- 渲染状态、图片校验值和发送状态
- 创建与最后更新时间

业务事务先写 `COMMITTED` 收据。重复事件查询到收据后不得重新执行领域服务。

发送状态采用 `PENDING -> CLAIMED -> SENT`，失败可记录为 `FAILED`。发送器先用条件更新领取一次发送权，再调用平台接口；进程若在平台已接收但状态尚未写成 `SENT` 时崩溃，重启后不自动重发 `CLAIMED` 收据，以牺牲极小概率的自动公示来保证不重复公示。用户仍可通过背包、详情或交易查询取得已提交结果。

## 6. 随机与规则版本

- 随机源通过接口注入，生产使用系统安全随机源，测试使用固定序列。
- 概率计算函数是纯函数，输入权重、升级、道具和资格，输出归一化权重与解释。
- 属性生成、价值、做菜品质和经验升级都使用纯函数并携带 `ruleset_version`。
- 每次结算把规则版本与关键输入写入实例或收据，方便复算。

## 7. 渲染管线

使用本地 HTML/CSS 模板和 `ctx.render.html2png()`：

1. 领域对象转换为无副作用的视图模型。
2. 对所有用户文本转义并限制长度。
3. 只引用插件资产和 `data_dir` 中当前群已授权素材。
4. 生成固定宽度、受限高度的 HTML。
5. SDK 返回 Base64 PNG 后，检查格式、解码、尺寸、文件大小和透明像素。
6. 调用 `ctx.send.image`。
7. 成功后清理临时文件；失败则记录并发送文字摘要。

渲染器不访问互联网。模板样式和素材加载必须在离线环境可用。

## 8. 素材导入

素材导入协议分为两个路径：

- 1 至 5 星公共素材：在 2B 随版本发布，通过同一清单协议导入。
- 6 星群素材：在 2B 导入数据目录，先落入暂存区，验证清单、图片、所属群和授权后再原子激活。

文件路径通过解析后的根目录校验，拒绝绝对路径、`..`、符号链接逃逸和无法识别的媒体。停用模板不删除历史行。

## 9. 安全与隐私

- 不记录 QQ 账号密码、Token、Cookie 或素材原始私密链接。
- 日志中的用户 ID 默认脱敏，调试级别也不输出完整交易对象。
- 6 星素材只在所属群渲染和查询。
- 管理操作写审计事件，包含操作者、范围、动作和结果。
- SQL 全部参数化。
- 资产描述只来自经过审核的静态数据，不把群聊文本拼成 HTML。

## 10. 可观测性与恢复

日志事件至少覆盖：

- 插件加载、数据库版本和素材统计
- 概率配置校验
- 抓取、做菜、售卖、赠送和交易的收据 ID
- 渲染与发送失败
- 账本不一致、资产状态冲突和迁移失败

2A 维护任务已支持：

- SQLite 一致性检查
- 数据库在线备份与保留数量清理
- 过期素材暂存目录清理

余额与账本对账、过期报价解锁和丢失素材扫描随对应玩法阶段实现。

这些工具默认只读或需要显式确认，不在插件启动时静默修复未知问题。
