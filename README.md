# MaiBot 抓猪插件

这是“抓猪插件”的独立 MaiBot 插件仓库。当前正式版本为 `1.22.2`；阿萨姆红茶奶雾锅的自动赠送带 PK 展示（原主→猪→发动者），且该次抓猪为额外次数不占正常额度。同名菜可直接按名称
快捷食用：存在多份时自动选择官方价值最低的一份，只剩最后一份时必须在 30 秒内用 `/是`
确认或用 `/否` 取消。`/使用道具 <道具名> [数量]` 可把同名道具排成连续使用队列；抓猪、
做菜及批量做菜回执会显示本次结算后的道具/多次菜品效果剩余次数。普通道具与非六星菜
效果可按队列顺序参与批量做菜，只有来源为六星菜的做菜效果仍要求逐只 `/做菜`。

做菜结果将最终品质概率、概率来源、成品效果和本次菜品加成拆成独立审计区，并随内容自然
增高，长效果不会再把概率挤出图片。糖醋排骨食用、
神龙化猪七星云海锅食用，以及糖醋排骨机会真正执行 `/重置额度` 时，会分别生成独立的
高规格“全群通告”长图。糖醋排骨首次通告只表示取得发动资格，不会冒充已经重置；真正发动
后再公示全群结算。`/今日巨物` 按北京时间当天展示当前群最大体型榜与最重体重榜。群级六星菜加成
在抓猪结果图和文字摘要中展示发动群友的 QQ 昵称，不再直接展示数字 QQ 号或
QQ 官方 OpenID；底层稳定身份仍保留用于审计和幂等。

  `/做菜`、`/批量做菜`、`/美食详情`、`/美食背包`、`/美食图鉴`、`/吃菜`（别名 `/使用美食`）、`/是`、`/否`、
  `/重置额度`（消耗六星菜重置机会，为本群重置一次抓猪额度）、
  `/猪猪商城`、`/购买`、`/升级`、`/售卖猪猪`、`/售卖美食`、`/批量售卖`、`/猪币账本`、
  `/猪猪赠送`、`/美食赠送`、`/猪猪交易`、`/美食交易`、`/接受交易`、

  `/切换 猪保千`（在保千猪立绘与猪保千表情包之间切换；多只保千猪时用 `/切换 猪保千 <编号>` 指定）；
  `/批量售卖 猪猪 三星`、`/批量做菜 三星` 等可按品质过滤批量处理（一星至五星）；
  `/开启批量保留`、`/关闭批量保留`（联动猪始终按每个联动品种保留价值最高的一只；
  开启后，普通猪猪和美食也按品种各保留一只价值最高的实例）

插件管理员另用 `/猪管帮助` 查看管理命令：可对当前群单人或全体已登记玩家发放/扣除
猪币（扣除后允许负余额），按名称或模板 ID 发放猪猪/美食，按精确短编号移除资产，
查看及维护插件/赠送/交易三类黑名单、查看或解除自动监管案件，并只重置一名玩家的
当前时段抓猪次数。
管理员手动编号允许 4 至 16 位英文字母或数字；省略时自动生成 8 位字母数字编号。
所有输入忽略英文大小写并以大写显示，新规则不会批量改写旧资产编号。

帮助保持纯文字，便于直接复制命令；已开放的业务结果优先发送白色、淡粉红图片，
图片渲染或发送失败时降级为完整文字，不回滚已提交的抓取、做菜、使用或经济结算。
默认抓猪基础概率为 `40% / 30% / 17% / 8% / 4% / 1%`；无当前群授权六星
素材时，最后 `1%` 转入五星。

## 正式运行

生产默认按北京时间 `00:00 / 09:00 / 12:00 / 19:00` 刷新，每群每人每个时段成功抓猪
`5` 次、每次成功后冷却 `20` 秒。自动备份每
`24` 小时执行一次并保留最近 `7` 份；维护任务不会静默修复账本或素材异常，只会记录
清晰日志并保留数据。

第六轮已完成正式素材隔离副本上的图片发送失败、数据库写锁、素材缺失、重启恢复、
双群隔离、账本对账和备份恢复演练。按用户决定，真实 QQ 群内的人机命令回归由用户
上线后自行执行，不作为自动化结果冒充记录。

正式美食素材已配置可验证的高星效果。效果在吃菜事务中进入持久队列，插件重启后仍在；
只在下一次兼容动作成功提交时消耗。正常额度由基础额度、永久额度、滚动七天额度、
当前时段额度、今日各时段额度和旧版全天共享次数池分层相加；六星菜专属次数绕过正常额度，
但仍受冷却和违规处罚硬上限约束。
不同菜品的效果签名互不重复。普通 4/5 星菜中，同一概率组一次最多生效最早的一个；
抓猪体型菜可再与一个抓猪概率菜及一个道具叠加；黑猪麻汤圆作为复合菜同时占用本次
抓猪概率位与体型位。普通五星“一猪六吃”、最多 5 层猪饺与超级主厨香料可以叠加，
统一上限为 `50%`。个人六星菜的独占抓猪/做菜效果仍从纯基础概率结算；神龙化猪七星
云海锅的全群下一次抓猪也采用同一独占边界。猪鼻蛋包饭恢复的两次 `60%` 六星做菜同样
按个人六星菜独占边界结算；其全群 `×1.004` 与做菜效果在同一次吃菜事务中原子登记。
糖醋排骨与猪鼻蛋包饭的全群时段倍率则可
与一个道具及非六星菜叠加，但多个全群六星菜倍率只取最高值。所有真正使用全群六星菜
加成的抓猪结果图与文字摘要都会展示“发动群友：QQ 昵称”，不展示数字 QQ 号或
QQ 官方 OpenID。
小马猪蒙布朗、雾蓝键盘大福和猪保千猪排轮盘的成功抓猪使用专属次数：不增加正常窗口
用量，正常额度为零时仍可触发；每次成功只扣一层菜品次数，冷却与违规处罚硬上限照常生效。
雾蓝键盘大福和猪保千猪排轮盘仅在各自剩余最后 1 次时启用 `50%` 六星小保底；若当前群
没有可用六星模板，无法实现的六星份额仍按既有规则转入五星。

需要人工管理时，可在 MaiBot 首页打开“抓猪运营管理”，进入插件配置的“额度重置”、
“赠送与交易黑名单管理”“自动监管”或“群公告发送”分区。自动监管案件可在目标群使用
`/猪管监管 [案件号]` 查看，并用 `/猪管监管解除 <案件号> [原因]` 人工解除；列表只显示尚未撤销且创建未满 24 小时的案件。
全局撤销与清零可先运行 `tools/reset_regulation_state.py` 预览，再显式追加 `--execute` 执行在线备份和原子重置。
一次性开关在执行外部操作前自动关闭，
避免配置重载或重启重复执行。QQ 官方 Bot 发送公告仍受平台权限约束：需要开启主动消息能力，
或目标群最近 5 分钟内存在可用的被动回复上下文；失败只记录审计和日志，不会自动重发。

单独重置额度时，也可在配置中填写精确群号、打开一次性开关并保存，或直接运行
`tools/reset_catch_quota.py --group-id <群号>`。两条路径都会先在线备份，再写入群级审计
事件，保留历史回执、资产和终身统计。完整操作见
[抓猪额度运维手册](docs/08-catch-quota-operations.md)和
[运营控制面板手册](docs/09-admin-panel-operations.md)。

## 不变原则

1. 只响应显式斜杠命令，不监听普通聊天，不使用 LLM。
2. `/抓猪帮助` 保持可复制纯文字；后续业务结果优先使用图片并提供文字降级。
3. 视觉以白色和淡粉红为主，不复制参考图的深蓝主题、水母素材、布局或文案。
4. 1 至 5 星使用公共素材；6 星按平台和群隔离，必须授权且支持撤回。
5. 金币、资产、料理、售卖和交易必须在事务中完成，并由消息回执保护幂等。
6. 只使用 MaiBot SDK 公共接口，不修改 MaiBot 核心代码。
