# 正式清单

`formal/pig-and-food-definitions.json` 是猪猪与美食的可审计元数据源，记录模板 ID、
显示名、品质、描述、素材相对路径、体型规则、美食效果、六星猪对应菜、
BanG Dream 联动信息和群作用域。

图片原件不放在 `catalogs/`；当前正式素材包位于 `asset_library/current/` 并通过 Git LFS
发布，MaiBot 运行副本位于插件数据目录。修改清单后必须运行
`tests/test_catalog_definitions.py` 和素材构建、导入校验，避免定义与二进制文件失配。

当前群专属内容同时维护四个作用域：`qq:1092931381` 与
`qq-official:5E5854406D0297D6FEAE696A13E3A339` 为一组，`qq:237716658` 与
`qq-official:9EA2810F378FBD7DC3219C56CEAB3520` 为一组。每个作用域各有 11 只六星猪和
11 道配对六星菜。修改任一群专属名称、描述、数值或效果时必须同步四份；
`tests/test_catalog_definitions.py` 会做全字段语义对比。

当前正式目录为 252 项：173 只猪、79 道美食。第八期公共内容包含 Ave Mujica `6/6`、
周四限定 KFC猪、咒术回战 `2/2` 及四道专属五星菜；这些公共模板由四个现有作用域共同读取，
不复制成群专属模板。

Ruleset 17 的公共四星、五星菜平衡只维护一份正式定义并由四个作用域共同读取；修改
效果类型、参数、次数或描述后必须重建 Asset Manifest。通常导入只影响此后生成的美食
实例；若运营明确要求存量菜同步，必须增加带版本、可测试的数据库迁移。Schema 20 是一次
明确例外：它更新本轮 9 道菜的可用/锁定实例和未消费队列，但不改写已处置资产或已完成效果。
Schema 21 继续收敛热加载期间可能产生的“猪利猪”中间参数，不改变其他菜品或历史终态。

Ruleset 27 重做猪利猪、猪皮奶、珍猪奶茶、雾蓝键盘大福、猪保千猪排轮盘和彩彩修车猪
慕斯。Schema 33 会同步更新正式模板、`ACTIVE/LOCKED` 实例与尚未消费效果，并把旧轮盘
效果转换为 3 次持久轮盘机会；已处置历史菜和已完成效果不追溯重算。专属五星菜仍必须
同时满足指定原料和五星品质结果，不能进入任何通用五星菜候选池。
Ruleset 28 不改素材定义：宿傩猪专属菜命中率为 `20%`，五条猪两道专属菜合计 `20%`
且各占 `10%`；KFC猪仍为 `50%`。本轮无需重建 Asset Manifest。
